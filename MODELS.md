# MODELS

Используемые модели, области применения, системные требования, ссылки на
Hugging Face. Документ обязателен по ТЗ, раздел 4.

Замеры, из которых взяты все числа, — [`WORKLOG/`](WORKLOG/README.md); разбор
выбора — [`docs/context/06-models.md`](docs/context/06-models.md); лицензии и
происхождение файлов — [`THIRD-PARTY.md`](THIRD-PARTY.md).

## Главное, что надо знать до таблиц

**Движок работает и без модели, целиком.** Разбор шаблона, сборка `.pptx` и
проверка вёрстки модель не зовут никогда, а раскладка контента умеет
обходиться без неё: `plan/deterministic.py` строит валидный план офлайн
(`ADR-0009`) — это и `--llm off`, и откат при любом отказе модели. Выньте вилку
из розетки — колода соберётся, только текст будет вашим, а не переписанным.

**Сеть по умолчанию выключена.** Режима три: `off`, **`cache` — по умолчанию**,
`on`. В режиме `cache` продукт читает коммиченные ответы и не делает ни одного
сетевого запроса (`ADR-0021`). Это не осторожность, а требование критерия 2:
эксперт без видеокарты обязан получить **наш** результат, а не тихо другой.

**С 25 сентября сборка зовёт модель** — для сплошного текста, одним запросом
на колоду (`PLAN-9.0`, Ш3; `ADR-0023`). Кэш ответов на запрос колоды пока пуст —
его наполнит сборка с `--llm on` (Ш8), — поэтому по умолчанию (`cache`) колода
собирается путём без модели, и сводка говорит это словами. Сдаточные колоды
собраны так же.

## Модели

Все замерены на нашей задаче, а не взяты по рейтингу. Лицензия каждой сверена по
карточке **конкретной модели**, а не семейства, — [`THIRD-PARTY.md`](THIRD-PARTY.md)
объясняет, почему это различие стоило отдельной проверки.

|---|---|---|---|---|
| **Qwen3.5-9B** (Q6_K) | 9B | Apache 2.0 | **зрение**: аудит слайда, контекстуальные проверки Приложения 1 | [`Qwen/Qwen3.5-9B`](https://huggingface.co/Qwen/Qwen3.5-9B) |
| **Gemma 4 12B it** (QAT Q4_0) | 12B | Apache 2.0 | **текст**: строит колоду из сплошного текста (с 25 сентября, `PLAN-9.0`); выбрана по разметке смысловых ролей | [`google/gemma-4-12B-it`](https://huggingface.co/google/gemma-4-12B-it) · [GGUF](https://huggingface.co/lmstudio-community/gemma-4-12B-it-QAT-GGUF) |
| Qwen3-VL-8B Instruct | 8B | Apache 2.0 | замерена, не выбрана | [`Qwen/Qwen3-VL-8B-Instruct`](https://huggingface.co/Qwen/Qwen3-VL-8B-Instruct) |
| Qwen3-4B Instruct 2507 | 4B | Apache 2.0 | замерена, не выбрана | [`Qwen/Qwen3-4B-Instruct-2507`](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507) |

**Чемпиона два, и это не нерешительность.** Замер 19 сентября при одном
фиксированном промпте:

| | Qwen3.5-9B Q6_K | Gemma 4 12B QAT Q4_0 |
|---|---|---|
| разметка ролей, строго | 83% | **89%** |
| **ложных «этой роли нет»** | **12** | **0** |
| зрение, вопросы по слайду | 4/5 | 4/5 |
| **различает пару «до ремонта / после»** | **да** | нет, угадывает |

По тексту решает не доля — там разница близка к шуму, — а двенадцать ложных
«этой роли в тексте нет» против нуля: диагностика, которая врёт двенадцать раз,
хуже отсутствия диагностики. По зрению решает единственный вопрос, который
вообще что-то значит для аудита: отличает ли модель сломанный слайд от
починенного.

**MiniCPM-V 4.5 и 4.6 замерены 19 сентября и отвергнуты**
([`WORKLOG/2026-09-19-minicpm.md`](WORKLOG/2026-09-19-minicpm.md)).

**Что даёт заказчик после топ-10.** Модель «Qwen 3.8 27b», и **инференс VK
обязателен**. До топ-10 не даётся ничего: «команда обеспечивает инференс
самостоятельно — на собственном GPU или через внешнего API-провайдера» (ТЗ,
раздел 3). Всё написанное здесь относится к отборочному этапу.

## Ограничения ТЗ, которым модели обязаны соответствовать

Раздел 3: **только открытые веса, лицензия Apache 2.0 / MIT, LLM/VLM/text-to-image
до 35B**. Все четыре модели проходят оба ограничения.

Два следствия, которые легко пропустить:

- **API допускается только для моделей с открытыми весами.** Поднять открытую
  модель на чужом GPU можно; обратиться к закрытой модели по API — нет.
- **Лицензия отсекает часть популярного.** SDXL идёт под CreativeML OpenRAIL++,
  а не Apache/MIT, и формально мимо требования.

## Системные требования

| | |
|---|---|
| **Движок** | Python 3.11, **обязательных зависимостей ноль**, модель не нужна |
| Проверка вёрстки (`--verify`) | Windows с установленным PowerPoint; без него стадия выключается сама |
| Тесты | `pytest`, `jsonschema`, `python-pptx` |
| **Модель локально** | видеокарта с ~9 ГБ свободной видеопамяти |

Замерено на RTX 4070 Super 12 ГБ: подъём модели занимает **4–7 с** и **9 ГБ
видеопамяти из 12**. Модель держится в памяти между вызовами, а не поднимается
на каждый: загрузка происходит один раз, дальше задачи идут потоком.

Сервер — `llama.cpp` (сборка b11011, ничего не устанавливалось):

```
llama-server.exe -m <веса.gguf> --mmproj <mmproj.gguf> -c 8192 -ngl 99 --host 127.0.0.1 --port 8080
```

Веса и сервер лежат **вне репозитория**: они чужие и весят гигабайты.

## Как это настраивается

Доступ к модели — файлом [`config/model.json`](config/model.json), не кодом
(`ADR-0022`): режим доступа, адрес, имя модели, таймаут, бюджет прогона,
параметры запроса, корни кэша. Файл несёт `version`, и она попадает в `deck-plan.json` вместе с
`sha256` — по артефакту видно, какими настройками он получен.

**Промпт модели — отдельным файлом, [`config/outline.json`](config/outline.json)**
(`ADR-0023`): общий текст и блоки двух режимов — «оставить мой текст» и
«доработать». Схема ответа и проверки ответа — в коде, `mimeo/plan/outline.py`:
это контракт, а не настройка (`ADR-0022`). Промпт заморожен до итогового замера
`PLAN-9.0`: правка — перемер на пяти текстах прозы корпуса в обоих режимах без
кэша промпта.

**Ключ API чужого инференса** — переменная окружения `MIMEO_LLM_API_KEY`; уходит
только в заголовок `Authorization: Bearer`, в конфиг и в кэш не попадает. Своему
`llama-server` ключ не нужен.

```
python tools/llm_probe.py            готова ли модель отвечать строгим JSON (схема прежнего контракта ADR-0010)
python tools/llm_cache.py list       что лежит в кэше ответов
python tools/bench_models.py --only gemma --no-think    сравнить модели на нашей задаче
```

**Проба спрашивает вызовом, а не каталогом моделей:** «сервер отвечает» и «модель
готова» — разные факты. Так было в LM Studio — он грузил модель по требованию и
выгружал по простою; от него отказались 24 сентября, но правило осталось: вызов
заодно проверяет, что модель отвечает по контракту.

## Четыре вещи, которые дорого стоили и которые стоит знать заранее

**Все пять испытанных моделей «думающие», и без отключения думания нерабочи.**
В запрос обязан идти `chat_template_kwargs: {"enable_thinking": false}`. Приём
`/no_think` в тексте **не действует**. Без параметра чемпион выдаёт 23 751 знак
рассуждения и до ответа не доходит вовсе.

**Умолчание шаблона — не то же, что умолчание сервера.** В чат-шаблоне Gemma 4
стоит `enable_thinking | default(false)`, но `llama-server` подставляет `true`
сам: без явного параметра — 477 знаков рассуждения, с ним — ноль. Прочитать
шаблон и сделать вывод недостаточно: надо послать запрос и посмотреть на ответ.
Поэтому `extra_body` и живёт в конфиге, а не в коде — рычаг у каждой среды свой.

**Промпт весит больше выбора модели.** Между двумя прогонами из системного
промпта убрали два слова — точность разметки упала с 67% до 56%. Это **больше**,
чем разница между квантованиями Q4 и Q8 в том же замере. Отсюда: сравнивать
модели можно только при одном фиксированном промпте, и называть, при каком.
И прежде чем менять модель — проверить, не в формулировке ли дело.

**Ответ зависит от предыдущего запроса, пока у сервера включён кэш промпта.**
`llama-server` по умолчанию берёт общее начало промпта из кэша прошлого запроса,
и при `temperature 0` ответ расходится: один запрос трижды вперемешку с другими
дал три разные колоды, с `cache_prompt: false` — одну и ту же
(`WORKLOG/2026-09-25-z57-sh1b-result.md`). Поле стоит в `config/model.json`
(`extra_body`); без него наполнение кэша ответов зависело бы от порядка сборки.

## Где модель применяется, а где нет

| Стадия | Модель | Почему |
|---|---|---|
| ANALYZE | **нет** | дизайн-система извлекается из XML точно |
| PLAN | **для сплошного текста, с 25 сентября** | `PLAN-9.0` (`Z-57`): модель строит колоду из текста до вёрстки — число слайдов, порядок, заголовки, тезисы, тип слайда, идеи картинок; шаблона не видит, ответ проверяет код. Размеченный вход и любой отказ — путь без модели: прозу на темы режет код (`ADR-0016`) |
| COMPOSE | **нет** | сборка детерминирована |
| VERIFY | **нет** | габариты даёт движок вёрстки (`ADR-0014`) |

**Чего модель не решает.** Цвета, шрифты, геометрию, вместимость слотов и
пригодность раскладки считает код. Отдавать это модели — менять точное на
правдоподобное (`ADR-0002`, `ADR-0009`).

**И чего она не делает ни при каких условиях:** не выдумывает содержания,
которого во входе нет. Нет во входе рынка — слайда «Рынок» не будет, и движок
скажет об этом в диагностике.

**Что проверяет код, а чего не видит.** Ответ модели принимается колодой
целиком, только если прошли все проверки (`mimeo/plan/outline.py`, `ADR-0023`):
числа текста на месте и чужих нет, каждая картинка — ровно на одном слайде,
латиница и название колоды — из текста, обращений к ассистенту и «Спасибо…» от
себя нет, в режиме «оставить» — фразы автора. На обложку идёт только название:
подзаголовок модели и картинка обложки на слайд не попадают и проверками не
считаются. Не прошла хоть одна проверка — колода собирается путём без модели.
**Оттенков смысла, слияния разделов и лозунга в режиме «доработать» код не
видит**: их держат режим «оставить», файл `outline.json` рядом с колодой
(текст, ответ модели, итог каждой проверки, что ушло в вёрстку) и просмотр
слайдов глазами. Режим по умолчанию — «оставить»: при отказе он уводит на путь
без модели, а не на пересказ.

**Тип слайда — довод, а не приказ.** Он поднимает раскладку своего вида, только
если содержание слайда способно её заполнить: под «крупное число» и «таблицу»
модель содержимого не даёт — тезисы у неё текстом, — и эти типы выбора не
меняют. Пункты оглавления собирает код из заголовков колоды и ставит их только
на макет оглавления, целиком и без пустых мест: на обычной раскладке пункты
читались бы как иерархия. Нет такого макета — оглавления в колоде нет, и
предупреждение это называет; на трёх выданных шаблонах с основным текстом его
нет.

**Идея картинки — пометка для генератора, а не часть вёрстки.** Модель одной
фразой называет, что нарисовать на слайде; в план колоды (`deck-plan.json`,
поле `image_idea`) код берёт её только на слайдах, где картинка не спорит с
содержанием (абзац, список, равные пункты, картинка с текстом), не на слайде с
картинкой автора, одну на поделённый раздел и не больше одной на три слайда
колоды; что не взято — называет предупреждение. Раскладку идея не меняет, сборка
её не читает — рисовать будет генератор отдельным планом (`Z-28`). **Качество
идей держит промпт, а не отбор:** у промпта 1.1 из 63 идей рисуемых сюжетов
4–8, остальное — графики, таблицы, значки и «фото команды»; промерены лучшие
формулировки, выбор — за пользователем (`WORKLOG/2026-09-25-z57-sh6-result.md`).

**Объём и длина текста.** Рамки объёма в промпте — `--slides`, а без флага —
рамки ТЗ, 10–15; модель их не добивает («если содержания меньше — меньше»), и
код без флага объём не подгоняет — как и без модели. **С `--slides` колоду
модели код тоже не добирает делением:** число слайдов — её решение, а добор
резал её слайд — таблицу из шести месяцев на три слайда по два, — и растр на
всех трёх выданных шаблонах был хуже колоды без добора. Не добрано — сводка
объёма говорит это словами; делится только слайд, который целиком не встаёт ни
в одну раскладку. Путь без модели добирает, как раньше (`ADR-0023`, «Что
уточнил Ш5»). Текст, который вместе с
промптом и запасом под ответ не влезает в контекст сервера, модели не
отправляется — путь без модели с заметкой: при 8192 токенах контекста и 4000 под
ответ это ~7.9 тыс. знаков (`config/model.json`, `chars_per_token`).
