# mimeo

Движок переноса стиля презентаций. На входе произвольный `.pptx`-шаблон и текст,
на выходе готовая презентация в стиле этого шаблона.

```
python -m mimeo build шаблон.pptx контент.md --output deck.pptx
```

Нужен только Python 3.11. **Обязательных зависимостей нет** — движок целиком
на стандартной библиотеке. `jsonschema` подключается опционально и только для
флага `--validate`; без него всё работает, проверка по схеме просто пропускается.

## Идея

Существующие инструменты генерируют содержание, а дизайн придумывают заново — и
на чужом шаблоне разваливаются, потому что воспроизводят только то, что сумели
понять.

Здесь наоборот: **дизайн извлекается из файла, а генерируется только текст.**

Слайд собирается **клонированием настоящего слайда шаблона** с подстановкой
содержимого в известные места. Всё, чего мы не поняли — тени, градиенты,
декоративная графика, привязка к теме, — приезжает вместе с клоном и выглядит
ровно так, как задумал дизайнер. На реальном шаблоне это до 767 фигур на колоду,
которые движок даже не разбирал.

## Стадии

| | Стадия | Что делает | Модель | Состояние |
|---|---|---|---|---|
| 1 | **ANALYZE** | шаблон → дизайн-система и библиотека паттернов | нет | готово |
| 2 | **PLAN** | текст + паттерны → план колоды | будет | путь без модели готов; клиента к модели нет |
| 3 | **COMPOSE** | план → `.pptx` клонированием донора | нет | готово |
| 4 | **VERIFY** | замер вёрстки → детект дефектов → ремонт плана → пересборка | нет | готово, флаг `--verify` |

Языковая модель будет работать **только в стадии PLAN** и только над тем, чего
код не умеет: понять, о чём абзац. Она не решает, что куда влезет, и не выбирает
порядок слайдов — это арифметика и код.

**Клиента к модели пока нет.** Контракт, схема ответа и его проверка написаны и
покрыты тестами, модель выбрана замером из семи кандидатов, но в продукт она не
подключена. Говорить о наполнении моделью в настоящем времени нельзя.

**Путь без модели полноценен.** Текст раскладывается и собирается целиком
офлайн: вынь вилку из розетки, и колода всё равно соберётся, только текст будет
вашим, а не переписанным.

**Вход не обязан быть размеченным.** Сплошное описание, как его пишут в чате,
разбирается на темы и тезисы детерминированным сегментатором (`ADR-0016`):
предложения, лексическая связность, обороты смены темы. Простыня в 1650 знаков
даёт 7–13 слайдов в зависимости от того, сколько раскладок в шаблоне. Модель
этот шаг потом улучшит, но не заменит.

**Где у этого граница, и мы её назовём сами.** Сегментатор опирается на обороты
смены темы, а они разговорные: «ещё важно», «теперь», «отдельно». **Деловой
текст, где темы помечены строками вида «По регионам:», он не режет** — отдаёт
один раздел на весь текст, и колода выходит пустой. Отказ при этом честный:
движок печатает, что не смог, и называет причину. Найдено нашим же корпусом
входов, чинится в `Z-39`.

## Что проверено

На корпусе из одиннадцати реальных файлов — семь настоящих презентаций на 9–48
слайдов и четыре мелких файла из тестового корпуса Apache POI, взятых ради
грязи; пять разных размеров холста, включая нестандартный 26.7 × 15 дюймов:

- разбор — без падений, доли секунды на файл;
- раскладка контента — без потерь на восьми шаблонах из одиннадцати;
- сборка — **11 из 11**, и каждый файл прошёл три независимые проверки:
  структурный валидатор, круговое чтение собственным разбором и открытие
  сторонней библиотекой `python-pptx`;
- **открытие в самом PowerPoint — 11 из 11.**

Последний пункт стоит отдельно, потому что он однажды разошёлся с предыдущим.
Два файла проходили все три структурные проверки и при этом **не открывались**:
терялись объявления пространств имён, на которые ссылаются значения атрибутов.
Ещё на трёх текст лежал в файле и не отображался. Отсюда правило, которым мы
теперь пользуемся: ноль структурных замечаний означает «структура
непротиворечива», а не «файл рабочий», — и единственная проверка, которая ловит
разницу, это открыть файл тем, чем его будут открывать.

Вёрстка измеряется тем же движком: переполнений текста по корпусу было **16,
после ремонта остался 1**; десять колод из одиннадцати чисты полностью.
Единственный оставшийся не ужимается дальше осознанно — его кегль уже у пола
читаемости, и уменьшать значит делать текст нечитаемым. Такой слот остаётся в
отчёте как неустранённый: «влезло, но не читается» хуже честного дефекта.

### И на шаблонах, которые выбирали не мы

15 сентября движок впервые встретился с материалом заказчика: три шаблона VK —
Tech, WorkSpace, Education — разобраны без падений, собраны и **открыты
настоящим PowerPoint**. Переполнения вёрстки **5 → 0, 3 → 0, 2 → 0** за 8–14
секунд при потолке задания в пять минут. Заглушки донора не протекли ни разу.

Это и есть проверка главного утверждения работы: шаблон выбирали не мы.

## Запуск

Все команды — из корня репозитория (каталог `mimeo/`).

```
python -m mimeo build   шаблон.pptx examples/content-demo.md --output out/deck.pptx
python -m mimeo analyze шаблон.pptx -o out --validate
python -m mimeo plan    шаблон.pptx examples/content-demo.md -o out --validate
```

Тесты и замеры:

```
python -m pip install pytest jsonschema python-pptx
python -m pytest
python tools/fetch_samples.py samples    # скачать корпус образцов
python tools/report.py compose           # таблица замеров
```

`python-pptx` нужен **только тестам**: он открывает собранные файлы как
независимый читатель. Сам движок его не использует.

Проверка вёрстки — стадия VERIFY: собрать, измерить, ужать непоместившееся,
пересобрать. Требует Windows с установленным PowerPoint и **запускает его на
рабочем столе**:

```
python -m mimeo build шаблон.pptx examples/content-demo.md -o out --output out/deck.pptx --verify
python tools/render_probe.py  out/deck.pptx -o out/render   # слайды в PNG
```

`--verify` — **штатный флаг продукта**, а не отдельный скрипт; отчёт по схеме
ложится в `<out>/render-report.json`. `tools/build_verified.py` делает то же
самое и оставлен ради флага `--rounds`.

### Три варианта вёрстки

Требование ТЗ, и оно закрыто (`ADR-0020`, `Z-26`). Движок порождает колоду на
каждую из 27 политик ранга (`config/variants.json`), оценивает весами и
отбирает те, что **заметно различаются** — не меньше чем на 30% слайдов:

```
python -m mimeo build шаблон.pptx examples/content-mimeo.md -o out --output out/deck.pptx --variants 3
```

Файлы получают суффикс `-1`, `-2`, `-3`. Порождение 27 планов стоит доли
секунды, весь комплект из трёх колод — около трёх секунд без проверки вёрстки
и около сорока пяти с ней.

Если шаблон беден раскладками и трёх непохожих колод из него не выходит, будет
собрано **меньше и названа причина**: выдавать почти одинаковые файлы за разные
мы не станем. По корпусу тройка собирается на 11 шаблонах из 14, включая все
три выданных организаторами; различие внутри тройки 33–58% слайдов.

«Одинаково соответствуют правилам шаблона» выполняется **по построению**: любой
вариант собран клонированием слайдов того же шаблона, чужих шрифтов, цветов и
макетов ни в одном нет.

Без Office стадия выключается сама, а обычная сборка работает как работала:
проверка вёрстки — инструмент качества, а не условие работы движка.

## Чего движок не умеет

Называем сами — полный список с числами в [`docs/STATE.md`](docs/STATE.md).

- **Деловой текст не сегментируется.** Разбор опирается на разговорные обороты
  смены темы. Текст, где темы помечены строками вида «По регионам:», отдаётся
  одним разделом — и колода выходит **пустой**. Отказ честный: движок печатает,
  что не смог, и называет причину. Найдено нашим же корпусом входов, `Z-39`.
- **Смысловой структуры повествования нет.** Порядок слайдов повторяет порядок
  абзацев входного текста. Каркас назначения — питч, отчёт, защита инициативы —
  спроектирован ([`docs/context/09-narrative.md`](docs/context/09-narrative.md)),
  но не построен.
- **Клиент к модели есть, потребителя у него нет.** Транспорт, кэш и откат
  написаны и покрыты тестами (`ADR-0021`), модель выбрана замером — но план
  колоды её пока не зовёт. Это осознанно: цена вызова измерена, выгода нет.
- **Авторские реплики и связки диктовки остаются на слайдах.** «Я этим
  горжусь», «теперь про то, что…» — речь автора о себе, а не содержание;
  отличить их грамматикой нельзя, это работа смысловой разметки (`Z-42`).
  *Обращения к исполнителю — «дальше скажи, что…», «в конце попроси…» —
  снимаются с 19 сентября: по корпусу было 10, стало 0; на колоде было семь
  слайдов из одиннадцати, стало ноль (`Z-41`).*
- **Заголовки разделов бывают обрубками фразы** — «Команду», «Шаблона Tech»:
  заголовок берётся из вводных слов, а не из смысла.
- **Проверка вёрстки находит дефекты, которые не может починить.** С
  19 сентября она видит текст, вышедший за нижний край своей плашки (`Z-38`), и
  отчёт вместо «переполнено 2 → 0, всё влезло» даёт «9 → 5» с перечнем слайдов
  и слотов. Но часть найденного неустранима: текст уже набран кеглем ниже
  порога читаемости, и ужимать дальше значит сделать его нечитаемым. Такой слот
  помечен неустранённым **сознательно**; лечится он выбором раскладки, а не
  ужиманием.
- **Донор с диаграммой или внедрённым объектом не переиспользуется.** Два клона
  делили бы одну часть, и PowerPoint отказался бы открывать файл целиком
  (`DOM-PKG §9`, `Z-44`). Пока это запрет на повтор, а не дублирование части:
  вместо повтора берётся следующая раскладка, и движок говорит об этом словами.
- **Данные диаграмм и содержимое таблиц не подменяются:** донор сохраняет свои.
  В отчёте об этом сказано явно.
- **Неиспользуемые медиа не вычищаются:** выходной файл несёт все картинки
  шаблона. Размер страдает, корректность нет.
- **Заметки докладчика не переносятся.**

## Как мы понимаем, что стало лучше

У колоды есть **измеримое качество** — пять счётных величин, сравниваемых по
старшинству, а не взвешенной суммой: потерянный контент, слоты, где текст сломан
безвозвратно, слоты с переполнением, разнообразие раскладок, слоты «на донышке»
(`mimeo/plan/quality.py`).

Взвешенной суммы нет намеренно: веса — это коэффициенты, а коэффициенты
подбирают под свой корпус. Здесь подгонять нечего.

Корпус при этом разделён: настраиваемся на одиннадцати шаблонах, которые
отбирали сами, а проверяемся на трёх выданных, которые выбирали не мы. И само
мерило испытано мутацией — заведомо испорченная колода обязана получить худшую
оценку, иначе оно бесполезно.
