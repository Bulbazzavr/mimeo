# 23 сентября: что модель делает с нашим текстом — замер до `PLAN-9.0`

Решение пользователя 23 сентября: подключать модель сейчас, а не после сдачи.
Прежде чем писать план — три замера. Код продукта не менялся.

```
python tools/llm_probe.py

```

12 282. Бенч повторил 19 сентября **до единицы**:

| demo, строго / мягко | 6/8 / 8/8 | 6/8 / 8/8 |
| зрение | 4/5 | 4/5, промах «обрезано» |
| пара «до/после» | различает | различает |

## 2. Что даёт путь без модели на основном тексте

```
python -m mimeo plan "tz/templates/2_Датасет VK Tech шаблон.pptx" examples/content-mimeo.md -o out/llm/plan-tech
```

13 слайдов. **Заголовков, которые читаются как речь, а не как заголовок, 7 из
13:** «В чём вообще беда», «На вход при этом идёт обычная сплошная речь»,
«Проверку вёрстки, это наша сильная часть» (винительный падеж), «По нашему
корпусу это дало 16 переполнений до и 1 после», «Про зависимости», «Насчёт
модели», «То, что нам нужно». Код их оставляет намеренно: склонять он не умеет,
а снятый предлог дал бы косвенный падеж (`Z-42`).

Тезисы в слотах — обрывки фраз: «А не гадаем по числу знаков, и если текст не
поместился».

**Порядок разделов близок к питчевому**, но не совпадает с ним: по ролям
Gemma (ниже) это обложка → проблема → решение → продукт ×3 → тяга ×2 →
продукт ×2 → модель → риски → просьба. Перестановка по каркасу (`Z-37`)
подняла бы два раздела о продукте выше тяги и сдвинула четыре слайда. Это
вопрос вкуса, а не видимый дефект.

**Поправка при перечитывании, до показа пользователю:** в первой редакции
здесь стояло «перестановка не изменила бы ничего». Порядок ролей это опровергает.

## 3. Модель на тех же разделах

Разовый скрипт `out/llm/probe_headings.py`, в репозиторий не входит. Один запрос
на колоду: для каждого раздела — заголовок (2–6 слов, именительный падеж),
1–4 тезиса до 90 знаков, роль; правило «только факты и числа из фрагмента».
Промпт один для обеих моделей, `temperature 0`, думание выключено.

| | Gemma 4 12B QAT Q4_0 | Qwen3.5-9B Q6_K |
|---|---|---|
| время на колоду, один вызов | 26.0 с | 21.3 с |
| токенов запрос / ответ | 1064 / **1244** | 1100 / 1177 |
| чисел, которых нет в тексте раздела | **0** | **0** |
| чисел раздела, потерянных в ответе | **0 из 10** | **2 из 10** («5», «300») |
| объём ответа к источнику | 81 % | 58 % |
| тезисов длиннее 90 знаков | 0 | 0 |
| роли | просьба, тяга, риски верны; **раздел о нейросети → «модель»**, а в словаре каркаса это бизнес-модель | «То, что нам нужно» → **рынок**; обложка → «продукт» |

Примеры Gemma: «Насчёт модели» → «Использование нейросети», «Проверку вёрстки,
это наша сильная часть» → «Проверка вёрстки», «То, что нам нужно» →
«Необходимые ресурсы». Нет ролей по её разметке: рынок, конкуренты, финансы,
команда, планы.

**Оговорки замера.** Разделы взяты из текстов слайдов готового плана, то есть
**после** вёрстки; в продукте запрос строится из разделов **до** неё, и их
число и границы могут отличаться. Проверка «ничего не выдумано» здесь только по
числам; оттенки вроде «значительно меньше лимита» кодом не ловятся.

## Что из этого следует для плана

1. Работа модели на нашем тексте — **заголовки и тезисы**, а не выбор раскладки
   и не порядок: порядок близок к каркасу, а разговорные заголовки видны на
   каждом слайде.
2. **Ролям нельзя верить без сверки:** слово «модель» в словаре — бизнес-модель,
   а модель отнесла к нему раздел о нейросети. Показанное «чего во входе нет»
   соврало бы.
3. **Один вызов на колоду**, 21–26 с — против 17.5–37 с у прежнего контракта
   «вызов на раздел» (`PLAN-2.6`, замер 9).
4. **Модель для текста — Gemma:** не теряет чисел и точнее в ролях. В
   `config/model.json` стоит Qwen.
5. **`max_tokens` 1200 в конфиге мал:** ответу Gemma нужно 1244.
6. Запрос содержит **только наш текст**, шаблона в нём нет — значит ответ можно
   держать в открытом кэше, и `OQ-33` снимается устройством запроса.

## 4. Модель строит колоду целиком — вторая часть замера

**Поправка пользователя к первой редакции плана:** по ТЗ сервис сам «определяет
состав слайдов, их последовательность и содержание до этапа вёрстки». Значит
модель получает **весь** текст, а не нарезку кода. Он же предложил выбор для
человека: оставить текст как есть или доработать, — и чтобы модель заранее
называла, какие картинки нужны по смыслу.

Разовый скрипт `out/llm/probe_outline.py`, Gemma 4 12B QAT, `temperature 0`,
думание выключено, контекст сервера 8192. Три текста корпуса разных форм, два
режима: `as_is` — тезисы дословно из текста; `improve` — переписаны, но только
факты текста. Слайдов просили «от 10 до 15; если содержания меньше — меньше,
ничего не выдумывая».

| Текст / режим | Слайдов | С | Числа: потеряно / выдумано | Картинки из текста | Тезисов дословно | Латиница не из текста | Идей картинок |
|---|---:|---:|---|---|---|---|---:|
| mimeo / as_is | 12 | 27.8 | 0 / 0 из 10 | 2 из 2 на месте | 28 из 30 | — | 1 |
| mimeo / improve | 12 | 27.1 | 0 / 0 | 2 из 2 | 2 из 32 | **Python** | 2 |
| prose / as_is | 12 | 26.3 | 0 / 0 из 19 | нет в тексте | 32 из 34 | — | 12 |
| prose / improve | 13 | 28.0 | 0 / 0 | — | 9 из 35 | **LTV** | 13 |
| numbers / as_is | 9 | 21.6 | 0 / 0 из 42 | — | 30 из 30 | — | 8 |
| numbers / improve | 10 | 25.8 | 0 / 0 | — | 0 из 34 | — | 9 |

**Что это значит.**

1. Колоду из сырого текста модель строит **одним вызовом за 22–28 с**, порядок
   разумный: на основном тексте обложка → проблема → решение → вход → разбор
   шаблона → проверка вёрстки (с картинкой) → результаты → воспроизводимость и
   зависимости (два раздела слиты в один) → модель → схема стадий (со второй
   картинкой) → ограничения → просьба.
2. **Числа: 0 потерянных и 0 выдуманных из 71** в каждом режиме. Пути картинок
   разложены точно, каждая — на один слайд.
3. **Короткий деловой текст дал 9 слайдов, а не 10:** модель не добивала объём
   выдумкой, как и просили.
4. **Недословных тезисов в `as_is` — 4 из 94:** три — грамматические правки
   фраз автора («схема четырёх стадий»), четвёртый — «Презентация движка
   mimeo» на обложке, взятый из **обращения к ассистенту** «Сделай, пожалуйста,
   презентацию про наш движок». Это класс `Z-41`, который код в своём пути
   вычищает; в пути модели его нужно ловить заново.
5. **`improve` дважды принёс латиницу, которой в тексте нет:** «Python» вместо
   «питона» и аббревиатуру «LTV». Проверка по латинице их ловит.
6. **Идеи картинок — почти на каждом слайде** там, где в тексте картинок нет:
   12 из 12 и 13 из 13. Столько генерировать незачем — нужен предел.
7. **Омоним держится и после переименования роли:** раздел о нейросети снова
   получил «бизнес-модель». Ролям по-прежнему нельзя верить без сверки.
