# 2026-09-09 · Разведка перед стадией PLAN

## Вопрос 1: поддерживают ли российские LLM структурированный вывод

Важно потому, что от ответа зависит, насколько оборонительным должен быть
промпт-контракт. Если структурированный вывод есть — можно просить JSON по
схеме. Если нет — придётся вытаскивать JSON из свободного текста и чинить.

**Найдено:**

| Модель | Структурированный вывод | Как именно |
|---|---|---|
| GigaChat | есть | Через function calling как совместимый путь; плюс нативные ограничения по JSON Schema на уровне API. `method="json_schema"` требует `gigachat>=0.2.1` и модель с поддержкой поля `response_format`. Поддержка со стороны GigaChat заявлена с версии 30.1, режим бета, предусмотрен откат на function calling |
| YandexGPT | есть | Параметр `response_format` с JSON Schema, формат совместим со спецификацией структурированного вывода OpenAI |

Источники: [ai-forever/gigachat, пример структурированного вывода](https://github.com/ai-forever/gigachat/blob/main/examples/example_structured_output.ipynb),
[langchain-gigachat, issue о поддержке](https://github.com/ai-forever/langchain-gigachat/issues/70),
[Yandex AI Studio, структурированный запрос](https://aistudio.yandex.ru/docs/en/ai-studio/operations/generation/completions-structured.html).

**Вывод для конструкции.** Структурированный вывод скорее всего будет, но
гарантировать нельзя: он бета, зависит от версии и от конкретной модели за
выданным API (`OQ-03`). Значит промпт-контракт строится **трёхрежимным**:

1. нативная JSON Schema через `response_format` — если поддерживается;
2. вызов инструмента с той же схемой — если поддерживается только это;
3. свободный текст, из которого JSON вытаскивается и чинится — всегда работает.

Режим определяется на старте пробным запросом, дальше не меняется. Валидатор и
ремонт одни и те же во всех трёх: **доверять режиму нельзя ни в одном из них**.

## Вопрос 2: что такое «Навык» в VK AI Space

Важно для `OQ-01`: в какой форме сдаётся решение.

**Найдено:** навыки на платформе — это «наборы инструкций, шагов и правил для
конкретной задачи, описанных на естественном языке без программирования». Один
навык переиспользуется разными агентами. Навыки разрабатываются внутри компании
**или подключаются из внешних источников**, исполнение происходит в контейнерах
в изолированном окружении.

Источники: [VK AI Space](https://tech.vk.ru/ai-space/),
[VK Tech: поддержка мультиагентных систем](https://tech.vk.ru/blog/na-platforme-vk-ai-space-poyavilas-podderzhka-multiagentnikh-sistem/).

**Вывод для конструкции.** Формулировка «описанных на естественном языке без
программирования» плохо вяжется с нашим движком: разбор OOXML на естественном
языке не опишешь. Зато «подключаются из внешних источников» и «исполнение в
контейнерах» вяжется хорошо: наш движок — внешний инструмент, который навык
вызывает.

Практическое следствие: **ядро остаётся библиотекой с чистым интерфейсом
вызова**, а адаптер под их CLI будет тонким слоем поверх. Это ровно то, что уже
записано в `CTX-TASK`, теперь с подтверждением. `OQ-01` остаётся открытым:
точная форма упаковки — из ТЗ 15 сентября.
