# Замеры перед `Z-39`: почему деловой текст не режется

19 сентября 2026. Снято **до** плана. Главный итог: **диагноз в карточке
неверен**, и правка по нему не помогла бы.

## Замер 1. Правило из карточки ловит один абзац из девяти

Карточка велит проверить правило «короткая строка, кончающаяся двоеточием, —
заголовок темы». Проверено на самом `examples/content-numbers.md`:

| Признак | Сколько абзацев из 9 |
|---|---|
| **кончается** двоеточием | **1** |
| двоеточие **в начале**, в голове нет точки | **6** |

Двоеточия стоят на позициях 14–40 знаков и **внутри** абзаца: «Среднее время
выдачи одного заказа: январь 2.8 мин…», «По регионам за июнь: Центр 22 400…»,
«Что предлагаем: открыть 12 пунктов…». Строка, кончающаяся двоеточием, здесь
одна — «Вот выдача по месяцам, заказов:» перед списком.

То есть правило, названное в карточке, покрывает **шестую часть** случаев,
ради которых заводилось.

## Замер 2. Механизм меток уже написан

`mimeo/plan/prose.py:180`:

```python
#: Короткая часть до двоеточия — метка темы: «Наша модель: подписка…».
_LABEL = re.compile(r"^([^:]{3,64}):\s+(.+)$")
```

И `group_topics` уже считает метку **самым крепким швом** между темами
(комментарий на строке 420). Расширять словарь маркеров смены темы не надо:
разговорные маркеры к делу не относятся вовсе, метка двоеточием работает и так.

## Замер 3. Настоящая причина: текст не входит в сегментатор

`_is_prose_section` (строка 642) требует, чтобы в разделе был **абзац длиннее
`prose_paragraph`**. Порог — 200.

Длины блоков `content-numbers.md`, посчитанные кодом:

| Блок | Вид | Знаков | Проходит порог 200 |
|---|---|---:|---|
| «Нужна презентация с цифрами…» | paragraph | 102 | нет |
| «Вот выдача по месяцам, заказов:» | paragraph | 31 | нет |
| список из шести месяцев | list | 84 | нет |
| «Среднее время выдачи одного заказа…» | paragraph | **184** | нет |
| «Доля заказов, выданных дольше…» | paragraph | 67 | нет |
| «По регионам за июнь…» | paragraph | 102 | нет |
| «Пунктов выдачи всего 318…» | paragraph | 83 | нет |
| «Нагрузка на сотрудника в пике…» | paragraph | 61 | нет |
| «Что предлагаем…» | paragraph | 162 | нет |

**Ни один.** Самый длинный — 184 при пороге 200. Значит
`needs_restructure` отдаёт `False`, и документ возвращается **нетронутым**:
один раздел, девять блоков, ни заголовка, ни темы. Отсюда и пустая колода.

Косвенное подтверждение: в диагностике плана **нет** строки «Вход распознан как
сплошная проза», которая есть у всех остальных входов корпуса. Сегментатор не
работал вовсе, а не работал плохо.

**Весь отказ держится на шестнадцати знаках.**

## Замер 4. Порог как причина — проверено решающим опытом

Порог меняется, всё остальное нетронуто. Числа — слайдов по 14 шаблонам
(11 наших + 3 выданных), «п» — сколько колод вышло **пустыми**.

| Вход | 200 (сейчас) | 180 | 150 | 120 | 90 | 60 |
|---|---|---|---|---|---|---|
| `content-chat` | 4-10 / п0 | 6-11 / п0 | 6-11 / п0 | 7-12 / п0 | 5-11 / п0 | 6-13 / п0 |
| `content-demo` | 6-7 / п0 | 6-7 | 6-7 | 6-7 | 6-7 | 6-7 |
| `content-mimeo` | 11-21 / п0 | 11-21 | 11-21 | 11-21 | 11-21 | 11-21 |
| **`content-numbers`** | **0-3 / п6** | 2-9 / **п0** | 3-9 / п0 | 3-9 / п0 | 4-11 / п0 | **7-11 / п0** |
| `content-prose` | 7-13 / п0 | 7-13 | 7-13 | 7-13 | 7-13 | 7-13 |
| `content-short` | 2-4 / п0 | 2-4 | 2-4 | 2-4 | 2-4 | 2-4 |

Два вывода, и второй важнее первого.

**Первый: порог и есть причина.** Уже 180 убирает все шесть пустых колод.

**Второй: понижение порога не трогает ничего, кроме больного.** Четыре входа из
шести дают ровно те же числа при любом пороге — `content-demo` размечен и не
сегментируется по построению, а `content-mimeo`, `content-prose` и
`content-short` это по одной сплошной простыне, и она проходит любой порог.
Регрессии, которой стоило бы бояться, **нет**, и это замер, а не надежда.

## Замер 5. Базовая линия: сколько слайдов даёт какой вход

Слайдов по 14 шаблонам, сегодня:

| Вход | Слайдов | Пустых колод |
|---|---|---|
| `content-numbers` | **0, 0, 0, 0, 0, 3, 1, 3, 3, 0, 2, 2, 1, 2** | **6 из 14** |
| `content-chat` | 9, 10, 6, 5, 5, 6, 6, 6, 6, 4, 5, 5, 5, 6 | 0 |
| `content-mimeo` | 18, 21, 11, 14, 14, 13, 12, 12, 12, 12, 12, 12, 12, 12 | 0 |

Карточка говорит «пусто на шести шаблонах из одиннадцати» — верно: все шесть
нулей приходятся на наши одиннадцать, на трёх выданных колода не пуста. Но и
там она **в 1–2 слайда** при требуемых ТЗ 10–15, то есть непригодна тоже.
Правильная формулировка результата — не «пусто на шести», а **«негодно на всех
четырнадцати»**.

## Замер 6. Соседний дефект, который правка размножит

Разделы получают **одинаковые id**. Считано по корпусу:

| Вход | Сейчас (порог 200) | При пороге 60 |
|---|---|---|
| `content-chat` | разделов 5, **дублей id 3** | разделов 6, дублей 5 |
| `content-numbers` | разделов 1, дублей 0 | разделов 7, **дублей 6** |
| остальные четыре | дублей 0 | дублей 0 |

Причина в `restructure`: короткий блок кладётся как
`ContentSection(id=section.id, …)`, а счётчик тем `for n, topic in
enumerate(topics, 1)` начинается заново **на каждом блоке**, давая `sec01t01`
всем.

**Это не косметика.** `deterministic.py` держит `forced: dict[str, int]` и
адресуется по `section.id` (строки 264, 312, 329, 386). Два раздела с одним id
делят одну запись: принудительное дробление одного молча применяется к
другому. Туда же `origin_section=section.id` (строка 411), по которому VERIFY
находит, чей слайд чинить.

**Сегодня дефект тихий — три дубля на одном входе. После правки `Z-39` их
станет одиннадцать.** Значит чинить надо вместе, иначе правка сделает хуже.

## Замер 7. Побочное из карточки подтвердилось

Заголовок колоды из «Нужна презентация **с цифрами** по загрузке…» не берётся:
в `config/prose.json`, `deck_title` лежат четырнадцать literal-фраз —
«презентацию про», «презентация о», «презентацию для», «слайды про» и подобные.
Шаблона «презентация \<что-нибудь\> по» среди них нет. Поэтому
`content-numbers` идёт без заголовка колоды и без обложки.

## Что из этого следует для плана

1. **Словарь маркеров смены темы расширять не надо** — он здесь ни при чём.
   Диагноз карточки заменить.
2. Чинить надо **ворота** `_is_prose_section`, а не порог сам по себе: порог
   отвечает на вопрос «резать ли этот абзац на тезисы», а его же спрашивают
   «проза ли это вообще». Два разных вопроса на одном числе.
3. Дубли id чинить **тем же коммитом**: правка превращает три в одиннадцать.
4. Мерить успех не «нет пустых колод», а **«слайдов 10–15 на сдаточных
   шаблонах»**: 1–2 слайда не лучше нуля.
