## Замок версий: проверено, что он умеет падать

Самое важное про эту задачу — не то, что замок есть, а то, что он **роняет**.

```
# дописан один перевод строки в config/prose.json, version не тронут
$ python tools/config_version.py --check
Замок и конфиги разошлись:
  prose.json: файл изменился, а version остался 1.0. Поднять version в файле,
  потом обновить замок (--write). Было ab85b771a0c5…, стало 67d675fce5b0…
exit=1

$ python tools/config_version.py --write
Замок не обновлён: сначала поднимите version.
  prose.json: содержимое изменилось, version прежний
exit=1
```

То есть `--write` не открывает замок тем же ключом, которым тот запирает.
После восстановления файла — `exit=0`.

## Три ошибки, которые нашла не голова, а проверка

**Первая: `io.open` без `import io`.** Убирая `import io` по замечанию ruff, я
не заменил один вызов. Все восемь тестов остались зелёными: они звали
`--check`, а сломанная ветка была в `--write`. Ветка, которую ни один тест не
исполняет, ломается молча. Заведён `test_write_produces_a_lock_that_check_accepts`.

**Вторая: в проекте две формы комментария в конфигах, а код знал одну.**
`"_"` — заметка про весь файл, `"ключ__"` — про соседний ключ
(`config/variants.json`, `config/prose.json`). Разбор `--config` пропускал
только первую, и половина пояснений уходила в «команда не знает таких ключей»,
выглядя россыпью опечаток. Нашёл тест на коммиченном примере.

**Третья: `model.py` перестал быть листом.** `ConfigStamp` сперва жил в
`mimeo/config.py`, и `model.py` его импортировал — а таблица границ модулей
(`ARCH`) объявляет `model` листом. Разрешено переносом: `ConfigStamp` — это
**форма артефакта**, её место в `model`, а чтение файлов импортирует оттуда.
Таблица границ дополнена строкой про `config`.

Ни одну из трёх не дало бы рассуждение: первую нашёл линтер, вторую — тест,
третью — чтение собственного документа.
