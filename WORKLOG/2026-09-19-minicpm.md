# 19 сентября — MiniCPM-V 4.5 и 4.6: обе отвергнуты, и польза не в этом

Замер по просьбе пользователя. План с двумя логическими проверками и обратным
планом от ИКР написан до прогона; семь находок, четыре из них — про то, как
отличить провал модели от провала измерителя.

**Итог: ни одна не принята.** Но замер дал две вещи ценнее вердикта: подтвердил
рычаг мышления на четвёртой и пятой модели подряд и **показал, что наша проблема
с `Z-34` решается не новой моделью, а переформулировкой вопроса**.

Воспроизведение:

```
python tools/bench_models.py --only minicpm --no-think --temp 0
```

## Что скачано и что говорят файлы

| | MiniCPM-V 4.5 | MiniCPM-V 4.6 |
|---|---|---|
| модель | `Q5_K_M`, 5.85 ГБ | `F16`, 1.52 ГБ |
| проектор | 1.095 ГБ | 1.109 ГБ |
| архитектура LLM | `qwen3`, **8.2B** | `qwen35`, **752M** |
| блоков / эмбеддинг | 36 / 4096 | 24 / 1024 |
| контекст | 40 960 | 262 144 |
| тип проектора | `resampler`, `minicpmv_version 6` | `minicpmv4_6` |
| объявленное сэмплирование | нет | temp 0.7, top_k 0, top_p 1.0 |
| **VRAM при `-c 8192`** | **8750 МиБ** | **3994 МиБ** |
| подъём | 7 с | 7 с |

Наша сборка b11011 поддерживает обе: в `mtmd.dll` есть **и `resampler`, и
`minicpmv4_6`**, в `llama.dll` — `qwen3` и `qwen35`. Проверено поиском строк в
библиотеках **до** запуска, а не выяснено падением.

**Расхождение источников:** GGUF 4.6 объявляет `top_k 0, top_p 1.0`, а
официальный cookbook рекомендует `top_k 100, top_p 0.8`. Совпадает только
температура. На результат это не повлияло: мерили при `temp 0`, как всех.

## Ш1–Ш2. Рычаг мышления: четвёртая и пятая модель подряд

Три вызова по нарастающей — текст, схема, картинка — каждый в двух вариантах.
Разделение на три уровня было находкой 1 плана, и оно окупилось сразу.

| | 4.5 | 4.6 |
|---|---|---|
| A текст, без параметра | 200 зн. рассуждения, ответ есть | 182 зн., ответ есть |
| A текст, `enable_thinking: false` | 0 зн., 2 токена | 0 зн., 2 токена |
| B схема, без параметра | **646 зн., `length`, ответ ПУСТ** | 259 зн., ответ есть |
| B схема, с параметром | 0 зн., `{"answer": "Париж"}` | 0 зн., `{"answer":"Paris"}` |
| C картинка, без параметра | **687 зн., `length`, ответ ПУСТ** | **853 зн., `length`, ответ ПУСТ** |
| C картинка, с параметром | 0 зн., «да» | 0 зн., «нет» |

**Рычаг тот же, что у наших:** `chat_template_kwargs: {"enable_thinking": false}`
в теле запроса. Серверный `--reasoning off`, которого требует официальный
cookbook, **не понадобился** — то есть наш `config/model.json` усмиряет обе с
первого раза.

**Без параметра обе ломаются ровно там, где важно** — на схеме и на картинке.
Если бы Ш1 не был разбит на три уровня, в журнал ушло бы «MiniCPM не отвечает по
контракту», и это было бы неправдой.

## Ш3–Ш5. Замер

Тот же промпт, что 17 сентября, `-c 8192`, `temp 0`.

| | 4.5 (8.2B) | 4.6 (752M) |
|---|---|---|
| prose, строго | 11/18 (61%) | **0/18** |
| demo, строго | 6/8 (75%) | **0/8** |
| зрение | 4/5 | **2/5** |
| **различающая пара** | **угадывает («да» на оба)** | **угадывает («нет» на оба)** |

### Ноль у 4.6 — это модель, а не измеритель. Проверено

0 из 18 за 0.3 секунды выглядит как отказ замерщика. Разбор сырого ответа
показал другое:

- **на `content-prose` модель вернула `units = []`** — пустой, но годный по схеме
  ответ. Грамматика соблюдена, сказано ничего;
- **на `content-demo` вернула 13 единиц с выдуманными идентификаторами** —
  `problem`, `solution`, `product`, `market`, `tension`, — вместо тех `b01`,
  `b02.0`, что были даны. Роли при этом русские и из нашего списка.

То есть модель **поняла предметную область и не поняла задание**: вместо разметки
данных фрагментов выдала правдоподобный общий список ролей, какой «должен быть у
презентации». Для нас это худший сорт ошибки — он выглядит как ответ.

Заодно это закрывает находку 5 плана: **язык ни при чём**. Русский промпт модель
прочитала, русские роли выдала; сломалось не понимание, а следование инструкции.

Ещё симптом того же: на вопрос «сколько карточек» 4.6 ответила **2400**.

## Полная картина зрения по всем замеренным моделям

| Модель | налож.-до | налож.-после | **пара** | карточек-3 | **обрезано** | карточек-4 | итого |
|---|---|---|---|---|---|---|---|
| Qwen3.5-9B | да ✓ | нет ✓ | **различает** | 3 ✓ | **нет ✗** | 4 ✓ | 4/5 |
| Gemma 4 12B | да ✓ | да ✗ | угадывает | 3 ✓ | да ✓ | 4 ✓ | 4/5 |
| MiniCPM-V 4.5 | да ✓ | да ✗ | угадывает | 3 ✓ | да ✓ | 4 ✓ | 4/5 |
| MiniCPM-V 4.6 | нет ✗ | нет ✓ | угадывает | **2400 ✗** | да ✓ | 3 ✗ | 2/5 |

**MiniCPM-V 4.5 повторила ответы Gemma слово в слово** — все пять, включая
ошибку. При этом текст у неё вдвое хуже (61% против 89%), а памяти она берёт
8750 МиБ. **Ниши нет ни одной:** на зрении не лучше того, что уже есть, на тексте
заметно хуже.

**MiniCPM-V 4.6** отвергается по совокупности: сломанное следование инструкции,
2 из 5 на зрении, абсурдные числа.

## Что оказалось ценнее вердикта

**Ни одна из четырёх моделей не берёт обе половины.** Кто проходит различающую
пару — ошибается на «обрезано»; кто отвечает про «обрезано» — угадывает на паре.
Четыре модели, два взаимоисключающих результата — это уже не про модели.

Вспомним замер 17 сентября: вопрос «есть ли заголовок, вторая строка которого
обрезана» провалили **все семь** испытанных моделей, а его предметная
переформулировка прошла на той же модели и той же картинке. Вывод тогда был:
**дело не в модели, а в вопросе.**

Вопрос различающей пары — «Перекрывает ли на этом слайде какой-нибудь текст
другой текст, налезая на него?» — **ровно такой же расплывчатый**. «Какой-нибудь
текст» не называет, на что смотреть.

**Следствие для `Z-34`, и оно не про выбор модели:** прежде чем искать зрячую
модель получше, надо переписать одиннадцать контекстуальных вопросов Приложения 1
в предметной форме — называя, на что смотреть. Это дешевле любой модели и уже
один раз сработало.

## Гипотеза сожительства ослаблена замером

Соблазн был такой: 4.6 весит 2.6 ГБ на диске, значит поместится в память рядом с
текстовой моделью, и переключать их не придётся.

Замер: 4.6 занимает **2981 МиБ сверх фона** (3994 при фоне 1013). Наши текстовые:
Qwen3.5 — 8118, Gemma — 8718. Суммы с фоном: **12 112 МиБ** (при потолке 12 282 —
запас 170 МиБ, то есть впритык) и **12 712 МиБ** — не влезает.

То есть «поместятся рядом» — про Qwen на грани фола, про Gemma неверно. Сумма
файлов на диске оказалась плохой оценкой памяти, и это стоило записать (находка 4
плана).

## Что изменено в инструменте

**Вердикт по различающей паре считается кодом и печатается строкой.** Раньше его
выводили глазами по двум строкам — и «нет/нет» при этом читалось как «1 из 2»,
то есть прилично. Теперь оба способа угадать называются вслух. Находка 2 плана;
проверено на всех четырёх исходах, включая «пары нет в прогоне».

**В шапке прогона печатается путь файла, а не только ярлык.** По метаданным 4.5
неотличима от обычного Qwen3-8B (`general.name = Model`, архитектура `qwen3`), и
перепутанный путь дал бы замер не той модели незаметно.
