## Что сделано

- **Флаги `--llm off|cache|on` и `--text keep|improve`** — у `plan` и `build`:
  модель живёт в стадии PLAN (`ADR-0023`). Допустимые значения берутся из самих
  модулей (`Access`, `outline.MODES`). Умолчание обоих — `None`: доступ без флага
  — из `config/model.json` (`cache`), умолчание режима текста выберет
  пользователь (Ш9).
- **Значение из конфига прогона проверяется своей проверкой** —
  `_check_model_args`: `choices` `argparse` на файл не действуют, и
  `{"llm": "maybe"}` прошёл бы молча. Командная строка по-прежнему важнее файла.
- **Строка «модель …» в трёх сводках** (`plan`, `build`, `build --variants`),
  функция `model_line`. Что она говорит сейчас, проверено запуском:

  | вход и флаги | строка |
  |---|---|
  | проза, `--llm on --text improve` | `on (задано при запуске, режим текста improve)`: колоду модель ещё не строит — подключение в Ш3; собрано путём без модели |
  | markdown, `--text improve` | не нужна: вход размечен, структуру задал автор; `--text improve` не применяется |
  | проза, без флагов (`plan`) | `cache (умолчание config/model.json)`: … собрано путём без модели |
  | `--llm maybe` | отказ разбора аргументов |
  | конфиг прогона `{"llm": "maybe"}` | `build: llm = 'maybe' — ожидается одно из: off, cache, on` |

  С `-q` строки нет — колоды не меняются. В `deck-plan.json` и `--report` она
  не пишется: причина уйдёт в диагностику вместе с `outline.json` в Ш3.
- **Ключ API** — `MIMEO_LLM_API_KEY`, читается в момент запроса, уходит только в
  заголовок `Authorization: Bearer`; ключ повторённый сервером в тексте отказа,
  вымаран (`***`). В тело и кэш не попадает — проверено тестом на поддельном
  сервере, который теперь пишет заголовки.
- **Замок** передаёт `--llm off` между флагами задания и хвостом (`command()`);
  хвост перекрывает — проверено разбором аргументов самого движка.
