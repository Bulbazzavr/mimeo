# 19 сентября — Gemma 4 12B QAT против чемпиона, и что оказалось с температурой

Пользователь скачал `gemma-4-12B-it-QAT-Q4_0` и спросил две вещи: оценить модель
и проверить, правда ли официальная рекомендация — температура 1.0.

**Обе проверены замером, а не чтением. Ответ на вторую: пользователь прав про
рекомендацию, и она ничего не меняет на нашей задаче.**

Воспроизведение:

```
python tools/bench_models.py --only gemma --no-think --temp 0
python tools/bench_models.py --only gemma --no-think --temp 1.0 --top-p 0.95 --top-k 64 --repeat 3
python tools/bench_models.py --only 3.5   --no-think --temp 0        # контроль
```

## Что объявляет сам файл

Прочитано разбором заголовка GGUF, а не взято с сайта:

| Ключ | Значение |
|---|---|
| `general.architecture` | **`gemma4`** |
| `general.sampling.temp` | **1.0** |
| `general.sampling.top_p` | 0.95 |
| `general.sampling.top_k` | 64 |
| `gemma4.context_length` | 262 144 |
| `gemma4.block_count` | 48, эмбеддинг 3840, голов 16 |
| `gemma4.attention.sliding_window` | 1024, с маской по слоям |
| словарь | **262 144** токена |
| чат-шаблон | встроен, 18 680 знаков |
| размер | 6.98 ГБ + проектор 0.18 ГБ |

**Рекомендованное сэмплирование лежит внутри самого файла.** Это сильнее любой
страницы в сети: значения положил туда конвертер Google. Веб-поиск подтверждает
те же три числа. Для сравнения: **оба наших Qwen не объявляют `general.sampling`
вовсе** — значит наш `temperature = 0` не нарушал ничьей рекомендации, он просто
был нашим выбором.

`llama.dll` и `mtmd.dll` нашей сборки b11011 содержат строку `gemma4` — то есть
архитектура поддержана, включая зрение. Проверено поиском строк в библиотеках, а
не запуском: сам `llama-server.exe` весит 9216 байт и является обёрткой, искать
в нём бесполезно.

## Ловушка: мышление включено, хотя в шаблоне написано обратное

В чат-шаблоне стоит `{%- set enable_thinking = enable_thinking | default(false) -%}`.
Прочитав это, я заключил, что параметр не нужен. **Замер опроверг чтение:**

| Запрос | Рассуждение | Токенов ответа |
|---|---|---|
| без параметра | **477 знаков** | 165 |
| `enable_thinking: false` | **0** | **19** |
| `enable_thinking: true` | 494 знака | 167 |

То есть `llama-server` подставляет `enable_thinking = true` сам, и умолчание
шаблона до него не доходит. Разница — **в 8.7 раза по токенам**.

Первый прогон замера без `--no-think` дал **семь отказов из семи**: на длинной
задаче разметки модель тратила лимит в 1200 токенов на рассуждение и до ответа не
доходила. Это дословное повторение случая 17 сентября с Qwen3.5, и вывод тот же:
**отказ измерителя — не приговор подопытному.**

Отдельно приятное: наш `config/model.json` шлёт `enable_thinking: false` всегда,
поэтому **клиент продукта обработал бы Gemma правильно с первого раза** — споткнулся
только замерщик, у которого это флаг.

## Числа: Gemma против чемпиона

Оба при `-c 8192`, все слои на GPU, мышление выключено, промпт **один и тот же**
(`SYSTEM_ROLES` из `bench_models.py`). Строка чемпиона — контрольный прогон
сегодня, а не цифры из прошлого файла: он воспроизвёл 17 сентября до единицы,
значит измеритель цел и сравнение честное.

| | Qwen3.5-9B Q6_K | **Gemma 4 12B QAT Q4_0** |
|---|---|---|
| файл + проектор | 7.36 + 0.92 ГБ | **6.98 + 0.18 ГБ** |
| свободно VRAM | **2867 МиБ** | 2265 МиБ |
| prose, строго | 15/18 (83%) | **16/18 (89%)** |
| prose, мягко | 15/18 (83%) | **17/18 (94%)** |
| prose, ложных «роли нет» | **12** | **0** |
| demo, строго | 6/8 (75%) | **7/8 (88%)** |
| demo, мягко | 8/8 (100%) | 8/8 (100%) |
| demo, пропуски | 8/8 (лишних 2) | 8/8 (лишних 2) |
| зрение | 4/5 | 4/5 |
| **пара «до/после»** | **различает** | **угадывает: «да» на обоих** |
| prose / demo, с | 11.1 / 5.8 | 10.9 / 6.5 |

**Главная разница — не в процентах.** По строгой доле обе выигранные Gemma
позиции — это одна единица из восемнадцати и одна из восьми; на выборке такого
размера это близко к шуму, и короновать по ней нельзя (ровно та ошибка, от
которой замер усиливали 17 сентября).

**Решает столбец «ложных пропусков»: 12 против 0.** Чемпион на прозе заявляет,
что двенадцати ролей в тексте нет, — а они есть. Для `Z-37` это не мелочь:
`CTX-NARRATIVE` разрешает движку **сказать словами, чего каркасу не хватает**, и
диагностика, которая врёт двенадцать раз из четырнадцати возможных, хуже, чем
отсутствие диагностики.

**И симметрично, столбец зрения решает против Gemma.** Она отвечает «да, есть
наложение» и на сломанном слайде, и на починенном — тот самый признак угадывания,
по которому 17 сентября отсеяли обе четырёхмиллиардные VL. Для `Z-34`
(контекстуальные проверки по картинке) это дисквалифицирует.

## Температура: пользователь прав про рекомендацию и не прав про последствия

Три прогона при объявленных моделью `temp 1.0, top_p 0.95, top_k 64`:

| Эталон | temp 0 | temp 1.0, прогон 1 | 2 | 3 | разброс |
|---|---|---|---|---|---|
| prose, строго | 16/18 | 16/18 | 16/18 | 16/18 | **0** |
| demo, строго | 7/8 | 7/8 | 7/8 | 7/8 | **0** |

**Разброса нет вовсе.** Единственное расхождение за три прогона — список
`missing_roles` в одном случае: `1/1` превратилось в `0/1` с одним лишним.

Правдоподобное объяснение: задача идёт **со строгой JSON-схемой**, а схема
срезает почти всю свободу сэмплирования — выбирать модели особо не из чего, и
температура не на что влиять. Проверять это утверждение на свободной генерации мы
не будем: свободной генерации у нас нет.

**Следствие:** оставляем `temperature = 0` и получаем байт в байт
воспроизводимые прогоны бесплатно. Рекомендация Google не нарушается в том
смысле, что она ничего не даёт на нашей задаче, — но это **наш замер на нашей
задаче**, а не опровержение рекомендации вообще.

## Что изменено в инструменте

`tools/bench_models.py`:

- **температура стала измеряемой величиной, а не константой.** До сегодня в теле
  запроса был вшит `temperature: 0` — незаметное допущение, которое для модели,
  калиброванной под 1.0, могло бы исказить замер. Теперь `--temp`, `--top-p`,
  `--top-k`;
- **`--repeat`**: при температуре больше нуля один прогон — шум, а не число.
  Печатается разброс по прогонам;
- **вывод переведён в UTF-8.** Печать стрелки «→» роняла весь замер
  `UnicodeEncodeError` в самом конце, после всей работы: консоль Windows — cp1251.
  Отказ измерителя не должен выглядеть как отказ модели.
