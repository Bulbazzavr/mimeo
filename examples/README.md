# Корпус входов

Наш собственный контент для проверок. Контент-пакета организаторы не дали
(`OQ-25`), поэтому пишем свой — и не один файл, а **корпус разных форм**
(`ADR-0017`, задача `Z-36`, план `PLAN-5.0`).

Корпус коммитится целиком: без него проект не воспроизводится с нуля, потому что
шаблоны в `samples/` чужие и в репозиторий не попадают.

## Зачем корпус, а не один текст

Один текст, написанный тем же, кто настраивает сегментацию, — это подгонка под
себя, и она незаметна. Несколько форм делают её видимой: правило, работающее
только на одном входе, обнаруживает себя сразу.

**Это не теория.** В первом же прогоне 19 сентября `content-numbers.md` дал
**ноль слайдов на шести шаблонах из одиннадцати**. На одном тексте этого
ограничения не было бы видно вовсе.

## Состав

| Файл | Форма | Что проверяет |
|---|---|---|
| `content-mimeo.md` | **основной**, сплошная речь, 2629 зн. (сокращён 27 сентября вечером, `Z-77`) | из него собираются девять колод сдачи |
| `content-prose.md` | стена текста без единого абзаца, 1651 зн. | худший случай сегментации |
| `content-demo.md` | размеченный markdown | контроль: структура задана явно |
| `content-chat.md` | смесь: абзацы, списки, числа, вопрос | типичный случай |
| `content-numbers.md` | числовые ряды с единицами | вход для графиков (`Z-32`); **ломает сегментацию — так и задумано** |
| `content-short.md` | заметка 220 зн. | честный отказ: 10–15 слайдов недостижимы |

Рядом лежат два эталона смысловой разметки, размеченные руками:
`content-prose.roles.json` и `content-demo.roles.json`. Ими сравниваются модели
(`tools/bench_models.py`).

## Про числа в текстах

**В `content-mimeo.md` все числа настоящие и прослеживаются до `WORKLOG/`.**
Это единственный текст, из которого собираются сдаточные колоды, и выдуманная
цифра в нём была бы ложью, которую эксперт проверит по нашему же репозиторию.

**В остальных числа выдуманы.** Они нужны только чтобы дать сегментатору и
разметчику материал нужной формы; ни одна презентация из них не сдаётся.

## Про картинки

`img/` — две PNG, нарисованные `tools/make_corpus_images.py` на стандартной
библиотеке. Растры наших собственных колод сюда не годятся: колода собирается на
**чужом** шаблоне из `samples/`, и её растр — производное от чужого дизайна.

Ссылки на них стоят в `content-mimeo.md`. **Работа тракта вставки изображений в
приёмку `Z-36` не входит** — это задача `Z-28`, и он ни разу не прогонялся.
