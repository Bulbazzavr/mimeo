# `tz/` — материалы ТЗ и всё, что из них собрано

Здесь лежит **только выданное организаторами и наши артефакты из него**. Ничего
своего сюда не кладём, ничего отсюда не смешиваем с `samples/` и `out/`.

Заведено 15 сентября 2026, в день открытия материалов (`Z-06`).

## Почему отдельно

**Разные права.** `samples/` — одиннадцать шаблонов, которые отбирал я сам:
прокси, отбор с уклоном. `tz/templates/` — оригинал, на котором оценивают. Числа
по ним нельзя складывать в одну таблицу, иначе непонятно, что чем подтверждено.

**Разный режим публикации.** П. 7.3.5 Положения объявляет данные ТЗ
конфиденциальными. **`OQ-22` снят 15 сентября чтением ТЗ:** требуется
«репозиторий с открытым доступом для экспертов», а артефакты грузятся на
платформу, а не в репозиторий. Значит конфликта нет — публикуем код и
документацию, а весь этот каталог целиком исключён из репозитория одной строкой
в `.gitignore`, а не перечислением файлов. Так нельзя опубликовать его случайно.

**Разная судьба.** `out/` затирается любым прогоном демо. Всё, что собрано из
материалов ТЗ, должно пережить эти прогоны.

## Что куда

```
tz/
  templates/   их шаблоны .pptx — как выдали, не переименовывать
  content/     их набор контента — текст, данные, картинки, если дадут
  out/
    analyze/   дизайн-система и библиотека паттернов по каждому шаблону
    decks/     собранные колоды
    render/    выгрузка слайдов в PNG — смотреть глазами
    verify/    отчёты стадии VERIFY, render-report.json
```

## Чего здесь быть не должно

**Ключей и адресов inference API.** Доступ к модели — не файл проекта: он идёт
переменными окружения, а не строкой в репозитории. Если ключ всё-таки оказался
в файле — файл удаляется, ключ отзывается и выпускается заново.

**Наших примеров.** Демо-контент живёт в `examples/` и коммитится: он написан
нами и нужен, чтобы всё воспроизводилось с нуля.

## Как этим пользоваться

```
python -m mimeo analyze tz/templates/<шаблон>.pptx -o tz/out/analyze --validate
python -m mimeo build   tz/templates/<шаблон>.pptx tz/content/<контент>.md \
                        -o tz/out/verify --output tz/out/decks/<имя>.pptx --verify
python tools/render_probe.py tz/out/decks/<имя>.pptx -o tz/out/render
```

Последние две поднимают настоящий PowerPoint на рабочем столе — **только с
согласия пользователя** (`ADR-0013`).
