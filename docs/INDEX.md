# Карта документации

Единая точка входа. Каждый документ имеет стабильный ID — на него ссылаются
комментарии в коде и другие документы.

## Четыре документа для эксперта · в корне репозитория

Их называет ТЗ, раздел 4, и эксперт пойдёт **по этим именам**, а не сюда.
Они не копия `docs/`: читаются подряд и ссылаются сюда за глубиной.

| Файл | Зачем |
|---|---|
| [../README.md](../README.md) | Сетап, переменные окружения, ограничения. Первое, что откроют. |
| [../ARCHITECTURE.md](../ARCHITECTURE.md) | Пайплайн и границы слоёв: парсинг, генерация, вёрстка, аудит, экспорт. Развёрнуто — `ARCH`. |
| [../MODELS.md](../MODELS.md) | Модели, области применения, системные требования, ссылки на huggingface. Разбор выбора — `CTX-MODELS`, лицензии — `THIRD-PARTY.md`. |
| [../web/README.md](../web/README.md) | Локальный веб-интерфейс: запуск, что умеет, чего не умеет намеренно, как устроена граница с движком. Не из списка ТЗ, но эксперт попадёт туда из `README`. |

## Правила ведения

- Новый документ обязан появиться в этой таблице, иначе его никто не найдёт.
- ID не переименовываются. Файл можно передвинуть, ID остаётся.
- Документ, потерявший актуальность, не удаляется, а получает в шапке
  `status: obsolete` и ссылку на замену.
- **Документ не обещает несуществующего.** Если написано «пересоздать скриптом» —
  скрипт лежит в `tools/` и запускается. Это проверяется тестом
  `tests/test_docs.py`: он же следит, что ссылки ведут в существующие файлы,
  каждый документ найден с этой карты и каждое решение перечислено выше.
