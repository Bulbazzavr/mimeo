# Текущее состояние

## Где мы

Пайплайн замкнут: **шаблон плюс текст на входе — готовый `.pptx` на выходе,
одной командой и без обращения к модели.** С 14 сентября текстом может быть
**сплошная проза из чата**, а не только размеченный markdown (`Z-25`,
`ADR-0016`): простыня в 1650 знаков даёт 7–13 слайдов на всех четырнадцати
шаблонах — одиннадцати наших и трёх выданных, — пустых колод ноль. С 15 сентября
объём задаётся флагом `--slides N` или `--slides N-M` (`Z-35`); без флага он
определяется контентом.

**Но «любая проза» — преувеличение, и это выяснилось 19 сентября.** Разговорная
диктовка режется хорошо. **Деловой текст, где темы помечены не вводными словами,
а строками вида «По регионам:», не режется вовсе**: сегментатор отдаёт один
раздел на весь текст, и колода выходит **пустой на шести шаблонах из
одиннадцати**. Отказ при этом честный — движок называет причину. Вскрыто
корпусом входов, задача `Z-39`.

**Корпус входов написан 19 сентября** (`Z-36`, `PLAN-5.0`): шесть форм в
`examples/`, основной текст про сам движок на числах из `WORKLOG`. Три шаблона
для девяти сдаточных колод выбраны замером — **выданные VK**, на них основной
текст даёт ровно по 11 слайдов при требуемых ТЗ 10–15.

|---|---|
| ANALYZE | закрыта целиком (1.1–1.6) |
| PLAN | путь без модели полноценен (`ADR-0009`). Сегментация прозы (`Z-25`), подгонка объёма (`Z-35`), **весы колоды** (`ADR-0019`) и **клиент к модели** (`Z-07`, `ADR-0021`): транспорт, кэш, откат. **Потребителя у клиента пока нет** — им станет `Z-37`. **Смысловой структуры нет** |

**15 сентября движок встретился с оригиналом.** Три выданных шаблона VK — Tech,
WorkSpace, Education — разобраны без падений, собраны и **открыты настоящим
PowerPoint**; переполнения вёрстки 5→0, 3→0, 2→0 за 8–14 секунд при потолке ТЗ в
пять минут. Заглушки донора не протекли ни разу. Это первая проверка главного
утверждения работы на материале, который выбирали не мы, и она пройдена
(`Z-06`, `WORKLOG/2026-09-15-tz-templates.md`).

Три дефекта нашего кода нашлись там же и починены: неэкранированный `&` в
гиперссылке делал пакет битым, зонд рендера падал на кириллице в пути, схема
запрещала слот с номером больше 99.

**Но ТЗ оказалось шире ответов организаторов** (`CTX-TZ`): веб-интерфейс —
требование, аудит должен показывать проблемы и спрашивать, что чинить, добавились
графики и версионирование скиллов. Разрыв переписан в `BACKLOG`.

Тесты проходят (`python -m pytest`). На корпусе из одиннадцати реальных файлов:
разбор без падений, план без потерь на восьми из одиннадцати, сборка и все три
проверки без замечаний на всех одиннадцати — и, что важнее, **все одиннадцать
открываются в PowerPoint**. До 12 сентября два из них не открывались, и ни одна
из трёх проверок этого не видела (`Z-20`).

**16–17 сентября: приёмка, весы и модель.** Пользователь впервые смотрел работу
блок за блоком. Главное утверждение — чужой шаблон, наш текст, его стиль — принято
на растре. Вёрстка принята не была, и разбор дефектов дал три вещи:

- **измеримое качество колоды** (`ADR-0019`, `mimeo/plan/quality.py`): пять
  счётных ступеней, сравнение по старшинству, корпус разделён на настроечную и
  отложенную части. Подгонять нечего, потому что весов нет;
- **решение порождать несколько колод и отбирать по весам** (`ADR-0020`) — замер
  показал, что противоречие «тесно против однообразно» внутри слайда не
  разрешается вовсе;
- **выбрана локальная модель** — чемпион из семи испытанных (`CTX-MODELS`).
  **Клиент к ней написан 17 сентября** (`Z-07`, `ADR-0021`): транспорт, кэш,
  поддельный сервер, проба среды. По умолчанию продукт в сеть **не ходит**.

**Главный пробел назван и не закрыт: смысловой структуры повествования нет.**
Порядок слайдов повторяет порядок абзацев входного текста. Что это значит и где
проходит граница «упорядочить найденное, но не выдумать недостающее» — в
`CTX-NARRATIVE`. Задача — `Z-37`, и она идёт следом за клиентом к модели.

Числа здесь — только те, что объясняют состояние. **Таблицы замеров не
дублируются**: они устаревают при каждом коммите, и две копии разошлись бы.
Порождаются `python tools/report.py compose`, сырые — в `WORKLOG/`, сводка для
питча — в `CTX-PITCH`.

```
python -m mimeo build путь/к/шаблону.pptx путь/к/контенту.md --output out/deck.pptx
python -m mimeo analyze путь/к/шаблону.pptx -o out --validate
python -m mimeo plan путь/к/шаблону.pptx путь/к/контенту.md -o out --validate
python -m pytest
```

Объём колоды задаётся флагом `--slides` у `build` и `plan`: `--slides 12` или
`--slides 10-15` (рамки ТЗ). Без флага объём определяется контентом — умолчание
отменено замером (`PLAN-2.3`). Цель — цель, а не гарантия: если контента или
раскладок не хватает, план говорит об этом словами.

Контент для проверок коммитится: `examples/content-demo.md` — размеченный
markdown, `examples/content-prose.md` — сплошная проза, как её описывает ТЗ.
Второй проходит через сегментатор (`ADR-0016`), первый — мимо него.

**Шаблоны в `samples/` не коммитятся** (они чужие) и в новой среде отсутствуют.
Восстановить и перезамерить:

```
python tools/fetch_samples.py samples
python tools/report.py compose
```

Собрать **с проверкой вёрстки** — стадия VERIFY целиком, в три раунда. Это
штатный флаг продукта; отчёт ложится в `<out>/render-report.json`:

```
python -m mimeo build samples/stilnyj-shablon-korporativnoj-prezentacii.pptx examples/content-demo.md -o out --output out/deck.pptx --verify
```

`tools/build_verified.py` делает то же самое и оставлен ради `--rounds`.

Открыть собранный файл в PowerPoint и выгрузить слайды в PNG:

```
python tools/render_probe.py out/deck.pptx -o out/render
```

Последние две команды — `build_verified` и `render_probe` — **поднимают
настоящий PowerPoint** на рабочем столе: нужны Windows, Office и согласие
пользователя (`ADR-0013`). Без Office стадия VERIFY выключается сама, а обычная
сборка `python -m mimeo build` работает как работала.

## Известные ограничения

### ANALYZE

- Библиотека паттернов почти один к одному со слайдами на дизайнерских
  шаблонах — следствие точного сравнения дробления полос (`ADR-0007`).
- Число колонок не определяется при свободной композиции.
- Фон слайда не наследуется от макета и мастера.
- `phClr` внутри стиля темы не подставляется; градиенты сводятся к первому стопу;
  текст таблиц не разбирается.

### PLAN

- **Заголовки, выведенные из прозы, бывают в косвенном падеже**: «Команду»
  вместо «Команда» — след фразы «расскажи про команду». Морфологии в стандартной
  библиотеке нет, и правилами это не чинится (`ADR-0016`). Исправит `Z-08`.
- **Плашки с числом из прозы не извлекаются.** `metric_value` держит 2–4 знака
  по корпусу, а числа в прозе идут с единицей: «120 миллионов рублей» не влезает
  ни в каком сокращении. Тоже работа модели.
- Детерминированный планировщик не сокращает текст: длинный заголовок ставится с
  переполнением и помечается `over_capacity` (`ADR-0009`). Ужимает его потом
  VERIFY, по факту рендера, — но **на сам флаг опираться нельзя**: замер показал
  полноту 36% и точность 57%, то есть он находит одно переполнение из трёх и в
  четырёх тревогах из десяти ошибается.
- **Смысловой структуры повествования нет.** Порядок слайдов повторяет порядок
  разделов входного файла. Флаг `--slides` меняет их число, но не порядок
  (`Z-35`). ТЗ требует обратного — «сервис определяет состав слайдов, их
  последовательность и содержание» по назначению (фича, продукт, проект,
  инициатива). Каркасы питча и отчёта, пирамида Минто, sparkline и **граница
  между «упорядочить найденное» и «выдумать недостающее»** разобраны 16 сентября
  в `CTX-NARRATIVE`. Задача — `Z-37`, делается вместе с `Z-26`.
- Двухслайдовые шаблоны теряют часть контента; потери перечислены в
  `diagnostics.unplaced`.

### COMPOSE

- **Пустые оформленные рамки.** Текст донора из незаполненных слотов убирается
  (`Z-18`), но сама фигура остаётся: скруглённая плашка, иконка без подписи.
  Чинится не очисткой, а рангом в PLAN — не выбирать раскладку, которую нечем
  заполнить (`Z-23`). **С 14 сентября дефект подорожал:** темы из прозы часто
  несут один-два тезиса, и на колоде из прозы пустые рамки видны на каждой
  третьей странице.
- **Слоты заполняются по ёмкости, а не в порядке чтения** (`Z-31`). На лесенке
  порядок повествования оказался обратным. Видно только растром.
- Данные диаграмм и содержимое таблиц не подменяются: донор сохраняет свои.
  В отчёте об этом сказано явно. Один видимый след на весь корпус — текст таблицы
  в `2411-Performance_Up` (`Z-12`).
- Неиспользуемые медиа не вычищаются: выходной файл несёт все картинки шаблона,
  включая не попавшие ни на один слайд. Размер страдает, корректность нет.
- Клон несёт и мусор донора — скрытые фигуры, заготовки за холстом.
- Заметки докладчика не переносятся: связь `notesSlide` вырезается (`ADR-0012`).

### VERIFY

- **Стадия стоит времени.** 1.6–13.7 с на колоду, медиана 4.4, из них
  60–70% — запуск PowerPoint. Поэтому `--verify` выключен по умолчанию.
- **Отчёт петли считает найденное, а не видимое.** 16 сентября на выданном
  шаблоне VK WorkSpace сборка сообщила «переполнено 3 → 0», а слайд с тремя
  видимыми дефектами не изменился ни на байт: ремонт чинил другие слайды. Строка
  отчёта правдива и вводит в заблуждение — читается как «колода чиста». Задача
  `Z-38`.
- **Текст, съезжающий со своей подложки при частичном перекрытии, не ловится**
  (`OQ-18`). Помехой считается фигура над или под текстом; плашка, которая
  перекрывает бокс лишь частично, границей не становится. **14 сентября случай
  наблюдался:** на колоде из прозы заголовок ушёл под карточку, и по нашей мерке
  место считалось свободным.
- **Чинится только переполнение по высоте.** Ширина меряется и попадает в отчёт,
  но не ремонтируется.
- **Переполнение устраняется не до конца.** По корпусу было **16, осталось 1**;
  десять колод из одиннадцати чисты полностью
  (`WORKLOG/2026-09-13-autofit.md`). Единственный оставшийся упёрся в предел
  читаемости: кегль уже у пола, и ужимать дальше значит делать текст
  нечитаемым. Такой слот остаётся в отчёте неустранённым **сознательно**:
  «влезло, но не читается» хуже честного дефекта.

  Прежние «37 → 8» относились к старой мерке дефекта, до `Z-24`. Здесь они
  простояли лишний день — ровно тот случай, когда закрытая задача оставляет
  устаревшее число там, куда не заглядывают.
- ~~Соседние слоты одной группы ужимаются по-разному~~ — **закрыто 13 сентября**
  (`Z-22`, `PLAN-4.1`). Слоты одной роли и одной высоты бокса получают общую
  шкалу: расходящихся групп было 3 из 10, стало 0. Признак группы измерен, а не
  назначен, — позиционный отпал на замере.
- Контраст и осиротевшие строки из `ADR-0005` не детектируются вовсе.
- **Работает только на Windows с Office.** Без них стадия выключается, а не
  роняет пайплайн (`ADR-0013`). Умеет ли LibreOffice сообщать габариты текста —
  открытый вопрос `OQ-16`.
