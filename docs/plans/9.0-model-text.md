# План: модель пишет заголовки и тезисы из нашего текста

Задача `Z-57`. Связаны: `Z-08` (вызов только для прозы), `Z-37` (роли и каркас —
потом), `OQ-33` (воспроизводимость сдаточных колод), `ADR-0021` (кэш прежде
сети), `PLAN-2.6` (клиент к модели). Решение пользователя 23 сентября: модель
подключаем сейчас, до сдачи, **не ломая нынешнюю работу**.

## Зачем

- Критерий 2 ТЗ прямо называет «оркестрацию CV/LLM», а сегодня модель в сборке
  **не вызывается ни разу** (`MODELS.md`).
- Вторая бизнес-задача ТЗ — «структура и текстовое наполнение по краткому
  брифу… до этапа вёрстки». Наполнение текстом — ровно работа для модели.
- Клиент, кэш, режимы, конфиг и поддельный сервер для тестов готовы с 17
  сентября (`PLAN-2.6`). Не хватает одного — **потребителя**.

## Замер до плана

`WORKLOG/2026-09-23-model-text.md`. Коротко:

| | Без модели | Gemma 4 12B | Qwen3.5-9B |
|---|---|---|---|
| заголовков-речи на основном тексте | **7 из 13** | 0 | 0 |
| время на колоду | — | 26.0 с, **один вызов** | 21.3 с |
| чисел не из текста | — | 0 | 0 |
| чисел потеряно | — | **0 из 10** | 2 из 10 |
| роли | нет | верны, кроме омонима «модель» | «просьба» → «рынок» |

**Что замер поменял в замысле, а не только в числах:**

1. **Работа модели — заголовки и тезисы, а не порядок и не раскладка.** Порядок
   основного текста близок к питчевому: перестановка по каркасу подняла бы два
   раздела о продукте выше тяги — это вкус, а не видимый дефект. Видимый
   дефект — разговорные заголовки и обрывки фраз в тезисах, и код его не берёт
   по построению: склонять он не умеет (`Z-42`).
2. **Один вызов на колоду**, а не на раздел: 21–26 с против 17.5–37 с у
   прежнего контракта `ADR-0010` (`PLAN-2.6`, замер 9).
3. **Модель для текста — Gemma:** не теряет чисел и точнее в ролях.
4. **Запрос несёт только наш текст, шаблона в нём нет** — отсюда разрешение
   `OQ-33` (ниже).

## ИКР

**Эксперт открывает девять колод и видит заголовки и тезисы, написанные
моделью из нашего же текста, — ничего не выдумано и не потеряно. Он собирает
их у себя без видеокарты и без сети и получает те же файлы байт в байт. С
видеокартой или по API он может позвать модель сам. А если модели нет или она
ошиблась, сборка идёт нынешним путём и говорит об этом словами.**

## Противоречие и как оно разрешается

**Техническое:** модель должна менять текст слайдов — иначе нет ни пользы, ни
оркестрации для критерия 2. И не должна — иначе пропадают воспроизводимость,
правило «не выдумывать» и проверенная вёрстка.

**Физическое, и оно острее:** ответ модели должен зависеть от входа, чтобы быть
полезным, и **не должен зависеть от шаблона**, чтобы его можно было положить в
репозиторий: кэш по выданным шаблонам коммитить нельзя (п. 7.3.5, `OQ-33`).

Разрешения, по приёмам ТРИЗ:

1. **Разделение во времени** (уже принято в `PLAN-2.6`): модель работает один
   раз, ответ ложится в кэш, дальше сборка — чистая функция от шаблона, текста
   и кэша.
2. **Разделение в структуре — новое.** Модель встаёт **до вёрстки**, на
   границе `ContentDoc → ContentDoc`: получает разделы нашего текста, отдаёт
   их же с заголовком и тезисами. Шаблона она не видит, значит ответ — наш, и
   кэш открытый даже для выданных шаблонов. `OQ-33` снимается устройством
   запроса, а не выбором из четырёх выходов `ADR-0021`.
3. **Разделение по условию.** Каждый ответ проверяет код; раздел, не прошедший
   проверку, собирается без модели, и это называется в диагностике.
4. **Посредник.** `ContentDoc` — готовая граница: `matching`, `compose` и
   `verify` не меняются вовсе. Пригодность и геометрию считает код (`ADR-0009`).

## Граница: что модель делает и чего нет

- **Делает:** для каждого раздела прозы — заголовок (именительный падеж,
  коротко) и от одного до четырёх тезисов. Роль из словаря каркаса приходит
  тем же ответом, но пишется **только в `rewrite.json`**: показывать её
  человеку рано (проверка 1, п. 10).
- **Не делает:** не видит шаблон, не выбирает раскладку, не меняет порядок, не
  пишет обложку (название продукта — авторское), не трогает числовые блоки,
  картинки, таблицы и цитаты.
- **Не вызывается для размеченного markdown:** там структуру задал автор
  (`Z-08`, так задумано с 13 сентября).

## Шаги

**Ш0. Замок «ничего не сломали» — до первой строки кода.** Снять `sha256`
девяти сдаточных колод и одиночных колод корпуса нынешним кодом. Приёмка всех
шагов ниже: с `--llm off` и при промахе кэша — **те же байты**.

**Ш1. Конфиг модели.** `config/model.json`: модель для текста — Gemma 4 12B
QAT; `max_tokens` 1200 → **4000** (ответу нужно 1244 — замер 3); версия
конфига и замо́к (`tools/config_version.py --write`). Формулировка промпта —
отдельным файлом конфига, как `config/prompt.json`; **схема ответа — в коде**:
это контракт, а не настройка (`ADR-0022`; проверка 1, п. 11). В словаре ролей
продукта «модель» → «бизнес-модель» (п. 10).

**Ш2. Доступ по API.** Ключ — из переменной окружения `MIMEO_LLM_API_KEY`,
заголовок `Authorization: Bearer`. **В конфиг и в кэш ключ не попадает**; ключ
кэша не зависит ни от адреса, ни от ключа — это уже так (`plan/cache.py`).
Флаг `build --llm off|cache|on` перекрывает поле `access` конфига.

**Ш3. Потребитель: `mimeo/plan/rewrite.py`.** Вход — `ContentDoc` из прозы,
выход — `ContentDoc` той же формы плюс заметки. Один запрос на колоду. Блоки
`paragraph` и `list` раздела заменяются одним `list` из тезисов на месте первого
из них; `metric`, `image`, `table`, `quote` остаются как были. Каталог кэша —
**по пути текста**, шаблон в выбор каталога не передаётся. Ответ и итог
проверок пишутся рядом с колодой, в `<out>/rewrite.json`: исходный раздел,
текст модели и что отвергнуто — чтобы «ничего не выдумано» можно было
проверить глазами, а не на слово.

**Ш4. Проверки ответа кодом.** Раздел принимается, только если:

- все его числа есть в ответе, и в ответе нет чисел, которых нет в разделе
  (на уровне `headings` из Ш5 — только второе, для заголовка: тезисы там не
  применяются; проверка 1, п. 12);
- слова латиницей в ответе есть в разделе (без учёта регистра);
- заголовок — от 1 до 7 слов, тезисов 1–4, каждый не длиннее 90 знаков;
- `id` совпадает, роль из словаря.

Не прошёл — раздел идёт без модели, причина — в `rewrite.json` и строкой в
диагностике. Ответ не разбирается вовсе — вся колода идёт без модели.

**Ш5. Два уровня применения, выбор замером.** Флаг конфига: `headings`
(меняются только заголовки) и `headings+theses`. Первый почти не трогает
вёрстку, второй меняет её везде. Какой ставить по умолчанию — решает Ш8, не
рассуждение.

**Ш6. Тесты на поддельном сервере и мутации.** Попадание в кэш; промах в режиме
`cache` → байты Ш0; `off` → байты Ш0; сервер лежит в режиме `on` → колода без
модели и заметка, а не падение; выдуманное число → раздел отвергнут; потерянное
число → отвергнут; ключ API уходит в заголовке; шаблон из-под `tz/` не
переводит кэш переписывания в `tz/`; markdown → вызова нет. Мутации — без `-x`,
две сверки: упал каждый новый тест **и** убита каждая мутация.

**Ш7. Наполнить кэш настоящей сборкой.** Не отдельным инструментом, а тем же
`build --llm on` — иначе запрос инструмента и запрос сборки разойдутся. Для
каждой поставляемой конфигурации: сдаточная команда (`--variants 3 --slides
10-15`) и умолчание веба. Кэш — в `cache/llm/`, в коммит. **Тест: ключ запроса
сдаточной команды есть в кэше** — правка промпта без перенаполнения иначе молча
вернула бы эксперту колоды без модели.

**Ш8. Замер после.** Девятка — `report.py verify`; корпус — `report.py
compose`; тройка вариантов на каждом выданном шаблоне; время колоды с моделью
и без; **растр всех девяти колод**; число картинок до и после — равно. Оба
уровня Ш5. Итог — в `WORKLOG`, выбор уровня — пользователю, с растром перед
глазами.

**Ш9. Веб.** Флажок «Звать модель» → `--llm on` с оговоркой «нужен сервер
модели»; строка о модели в результате. Коммит с соавтором.

**Ш10. Документы.** Новое решение — ADR под следующим свободным номером:
модель переписывает разделы до вёрстки; `ADR-0010` в части задачи модели —
superseded; `MODELS.md` — что делает
модель, какая, три способа запуска: кэш, своя видеокарта, API; `README` —
таблица стадий; `ARCHITECTURE`; `SPEC-WEB` — флаг `--llm`; `OQ-33` закрыт;
`BACKLOG`, `STATE`, `ПЛАН-MIMEO.md`. `doc_check` чист.

**После плана:** `Z-56` и `Z-55` — уже на новом тексте. Видео — после Ш9: в нём
должна быть видна модель.

## Приёмка

1. `--llm off` и промах кэша — байты Ш0 на всех колодах Ш0.
2. Режим `cache` на сдаточной команде даёт колоды с текстом модели; без сервера
   модели — **те же байты**, что с ним.
3. Во всех принятых разделах чисел не выдумано и не потеряно — по построению
   Ш4; отвергнутые названы.
4. Растр девяти колод просмотрен; новых видимых дефектов нет или они названы и
   взвешены. Тройка вариантов на всех трёх выданных шаблонах.
5. Колода с моделью не дольше 5 минут.
6. Тесты зелёные, обе сверки мутаций.
7. `doc_check` чист; документы не обещают того, чего нет.

## Логическая проверка 1: ошибки и дыры

1. **Кэш привязан к точному запросу, а запрос — к флагам.** `--slides 10-15`
   меняет нарезку разделов (`load_content(target=…)`), значит и ключ. Веб без
   этого флага попал бы мимо кэша. → В Ш7: наполнять под **каждую**
   поставляемую конфигурацию.
2. **Правка промпта молча обесценивает кэш**, и эксперт получит колоды без
   модели, не узнав об этом. → Тест «ключ сдаточного запроса есть в кэше»
   (Ш7).
3. **Замер делался на текстах слайдов после вёрстки**, а продукт спросит
   разделы до неё. → Числа Ш4 перемерить на настоящем запросе (Ш8), старые не
   переносить.
4. **Проверка латиницы может браковать хорошее:** Gemma написала «Python», а в
   тексте — «питона». → Сначала замерить долю отказов на корпусе; лечить
   промптом («названия — как в тексте»), а не ослаблением проверки.
5. **Картинки и числовые блоки не должны потеряться при замене блоков.** → Ш3
   трогает только `paragraph` и `list`; в Ш8 — сверка числа картинок.
6. **Обложка — название продукта, авторское.** → Не переписывается (граница).
7. **Длинный вход не влезет в контекст 8192.** Наш текст — 2.3 тыс. токенов на
   всё. → Порог по длине: выше — колода без модели с заметкой. Резать на части
   сейчас не будем: на входах корпуса и ТЗ (10–15 слайдов) порог не
   достигается.
8. **`llm_cache.py fill` строит запросы сам,** по контракту `ADR-0010`. Второй
   построитель запроса разойдётся с первым. → Ш7 наполняет кэш самой сборкой.
9. **Ни одна проверка не видит смысловых оттенков** («значительно меньше
   лимита»). → Названо в `MODELS.md`; для этого и `rewrite.json` рядом с
   колодой, и растр с глазами в приёмке.

Ещё четыре нашлись **перечитыванием данных замера**, а не плана:

10. **Роли врут на омониме.** Раздел о нейросети Gemma отнесла к «модели», а в
    словаре каркаса «модель» — бизнес-модель. Строка «во входе нет: …»
    назвала бы бизнес-модель присутствующей. → Роли — только в
    `rewrite.json`; человеку их не показывать, пока не сверены с эталоном; в
    словаре продукта — «бизнес-модель» (граница, Ш1).
11. **Схему ответа нельзя выносить в конфиг:** `ADR-0022` оставил её в коде
    сознательно — контракт, а не настройка. Первая редакция Ш1 это нарушала.
    → В конфиге только формулировка промпта.
12. **На уровне `headings` проверка «числа не потеряны» бессмысленна:** тезисы
    там не применяются, и она браковала бы разделы ни за что. → Ш4 разводит
    проверки по уровням.
13. **Первая редакция утверждала, что перестановка по ролям «не изменила бы ни
    слайда».** Порядок ролей Gemma это опровергает: два раздела о продукте
    стоят после тяги. Вывод «работа модели — текст, а не порядок» устоял, довод
    к нему заменён (раздел «Замер до плана», п. 1).

## Логическая проверка 2: правки сошлись? не делаем ли мы не то?

**Правки 1–13 внесены** — в Ш1, Ш3, Ш4, Ш7, Ш8, границу и раздел замера.
Правка 8 убрала целый шаг: отдельного наполнителя не будет. Сверено
построчно: Ш1 больше не выносит схему, Ш4 разводит проверки по уровням, граница
не обещает показывать роли.

**Не то ли делаем — пять вопросов.**

1. *Может, модели нужны роли и каркас, как писал `PLAN-2.6`?* Каркас — это
   порядок, а порядок основного текста близок к верному: расхождение в двух
   разделах, и это вкус. Роли приходят тем же вызовом, но **человеку пока не
   показываются**: омоним «модель» показал, что без сверки с эталоном строка
   «чего во входе нет» соврёт. Каркас и показ ролей остаются `Z-37`.
2. *Не противоречит ли это «текст ваш, мы не сочиняем»?* Модель **сжимает** ваш
   текст, а числа и названия сверяет код. Формулировку в `README` и `MODELS`
   придётся поменять — честно, в Ш10. И `--llm off` возвращает прежнее.
3. *Не рано ли, за шесть дней до сдачи?* Риск ограничен: без модели — те же
   байты (Ш0), с моделью — проверка на каждом разделе. Но колоды меняются
   **все**, и замеры вёрстки, включая `Z-55` и `Z-56`, снимаются заново. Это
   цена, и она названа.
4. *Нет ли пути проще — ИКР «само собой»?* Переписать `content-mimeo.md` руками
   красиво и оставить код как есть — девять колод станут лучше без всякой
   модели. **Это подмена:** оркестрации в продукте не появится, а текст
   эксперта не станет лучше ни на слово. Отвергнуто.
5. *Не заменяем ли проверку верой?* Польза показана **на одном тексте** одним
   зондом. Поэтому Ш5 держит два уровня, а Ш8 выбирает между ними растром и
   корпусом, а не впечатлением от тринадцати заголовков.

## Обратный план от ИКР

Иду от конца назад и сверяю с прямым.

1. **Эксперт без видеокарты получает те же файлы** ⇐ кэш попадает в ключ
   сдаточной команды ⇐ кэш в репозитории ⇐ в запросе нет данных ТЗ ⇐ модель
   видит только текст. ← Ш3, Ш7, тест Ш7. Сходится.
2. **Текст модели хороший** ⇐ выбран замером уровень применения ⇐ растр и
   корпус ⇐ выбрана лучшая модель. ← Ш1, Ш5, Ш8. Сходится.
3. **Ничего не выдумано и не потеряно** ⇐ проверки кодом ⇐ отказ по разделу.
   ← Ш4. Сходится. **А эксперт может это увидеть сам?** ⇐ исходник и ответ
   рядом с колодой. ← В первой редакции прямого плана этого не было;
   `rewrite.json` добавлен в Ш3 **этим проходом**.
4. **С видеокартой или по API эксперт зовёт модель сам** ⇐ флаг `--llm on` ⇐
   адрес и ключ ⇐ описано в `MODELS.md`. ← Ш2, Ш10. Сходится.
5. **Отказ модели не ломает сборку и слышен** ⇐ откат по разделу и по колоде ⇐
   заметка в диагностике. ← Ш4, Ш6. Сходится.
6. **Нынешняя работа не сломана** ⇐ байты Ш0 при `off` и промахе. ← Ш0, Ш6.
   Сходится.
7. **Видео показывает модель** ⇐ её можно включить из веба ⇐ флажок. ← Ш9.
   Сходится; и отсюда порядок: видео — после Ш9.

**Расхождение нашлось одно — пункт 3:** прямой план проверял текст модели, но
не давал проверить его эксперту. Закрыто в Ш3.

## Что за пользователем

- **Решение по плану.** Без него код не пишется.
- **Выбор уровня Ш5** — после растра девяти колод.
- **Видео** — после Ш9.
- **Модель для картинок** — отдельным планом, когда пользователь её передаст;
  первая проверка — лицензия: только Apache 2.0 или MIT, генерация до 20B
  (ТЗ, п. 3.1).
