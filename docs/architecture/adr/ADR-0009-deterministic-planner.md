# ADR-0009. Планировщик без модели — основа, а не запасной путь

## Контекст

По ТЗ стадия PLAN опирается на языковую модель. Соблазн — так и написать: взять
контент, отдать модели, получить план. Тогда до 15 сентября, пока не открыт
доступ к inference API, стадию нельзя ни запустить, ни протестировать, а стадия
COMPOSE остаётся без входных данных.

Есть и второй мотив, не про удобство разработки. Питч проходит онлайн 23 октября.
Падение на глазах у комиссии из-за недоступности чужого сервиса — реальный риск,
и закрывать его надо конструкцией, а не надеждой.

## Решение

Строится **полноценный планировщик, не обращающийся к сети**. Он раскладывает
размеченный контент по паттернам шаблона и выдаёт валидный `deck-plan.json`.

Разделение труда с моделью проведено так:

| Что | Кто | Почему |
|---|---|---|
| разбор контента на блоки | код | это разметка, а не смысл |
| **пригодность** паттерна: хватает ли слотов, влезает ли текст | код | это арифметика |
| **выбор** из пригодных | модель | это смысл: «сравнение по годам» просится в две колонки |
| текст в слотах | модель | ради этого её и звали |
| дробление длинного раздела на слайды | код | это счёт, а не сочинение |

Модель, когда появится, получит **тот же ранжированный список пригодных
паттернов** и заменит собой только один шаг — выбор и формулировки. Всё
остальное уже работает.

## Что это даёт, кроме тестируемости

**Проверяемая формулировка для питча.** Выньте вилку из розетки — колода всё
равно соберётся, только текст будет вашим, а не переписанным. Ни у одной обёртки
над LLM такого свойства нет по построению.

**Эталон.** План, построенный моделью, обязан пройти тот же валидатор, что и
план, построенный кодом. Если не проходит — виноват не валидатор.

**Честная деградация.** Когда API недоступен или ответ модели невосстановимо
испорчен, система не падает, а откатывается на этот путь и пишет об этом в
`diagnostics.planner`.

## Что показал замер

На корпусе из одиннадцати реальных шаблонов и одном демо-контенте из пяти
разделов: восемь шаблонов из одиннадцати разложены **без потерь**. Оставшиеся
три — двухслайдовые файлы, где паттерны выведены из макетов (`ADR-0006`), и
потери там честно перечислены в `diagnostics.unplaced`.

На дизайнерском шаблоне колода вышла осмысленной: обложка → списки → карточки →
картинка с текстом → две колонки → раздел. Без единого обращения к модели.

## Следствия

**Плохо.** Детерминированный планировщик использует текст пользователя как есть.
Если заголовок раздела длиннее ёмкости слота, он не сократит его, а поставит с
переполнением и пометит флагом. Сокращать — работа модели.

**Плохо.** Порядок слайдов повторяет порядок разделов входного файла. Нарратив
он не выстраивает; это тоже работа модели.

**Хорошо.** Оба ограничения ровно те, ради снятия которых модель и нужна. То
есть её вклад становится измеримым: разница между двумя планами по одному
контенту — это и есть ответ на вопрос «что дала нейросеть».

## Что изменилось с тех пор · 24 сентября

**Две строки таблицы разделения труда заменены `ADR-0023`.** «Выбор из
пригодных — модель» стал делом кода: модель шаблона не видит, а тип слайда из её
ответа — довод в ранге, не приказ. «Текст в слотах — модель» стал «текст колоды —
модель, до вёрстки»: по слотам его разносит код. Принцип в силе целиком: путь без
модели — основа, он же `--llm off` и откат при отказе, и его байты держит замок
Ш0 (`tools/deck_lock.py`).
