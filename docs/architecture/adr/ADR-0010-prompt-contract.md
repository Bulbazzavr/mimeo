# ADR-0010. Промпт-контракт: три режима отправки, одна проверка

## Контекст

Неизвестно, какая модель стоит за выданным организаторами inference API и что
она умеет (`OQ-02`, `OQ-03`, `OQ-11`). Писать под конкретный API нельзя — его
ещё нет; не писать ничего тоже нельзя — тогда 15 сентября придётся начинать с
нуля в самый дорогой момент.

Разведка (`WORKLOG/2026-09-09-stage-plan.md`): и GigaChat, и YandexGPT
принимают JSON Schema. У GigaChat это поле `response_format`, поддержка заявлена
с версии 30.1, режим бета, предусмотрен откат на function calling; у YandexGPT —
`response_format`, совместимый со спецификацией OpenAI. То есть
структурированный вывод **скорее всего** будет, но гарантии нет: он зависит от
версии и от конкретной модели.

## Решение

Пишется **контракт, а не промпт**. Формулировки инструкций поменяются под
конкретную модель за полчаса; меняться не должны три вещи.

**1. Что уходит.** Кусок контента плюс каталог **пригодных** паттернов: для
каждого — идентификатор, назначение и список слотов с ролью, типом и лимитами.
Геометрии в каталоге нет: координаты модель не видит и видеть не должна
(`ADR-0002`). Пригодность считает код (`ADR-0009`), модель выбирает из готового.

**2. Как уходит.** Три режима, от лучшего к запасному:

| Режим | Когда | Что делаем |
|---|---|---|
| `json_schema` | API принимает `response_format` со схемой | отдаём схему ответа |
| `tool_call` | есть только вызов инструментов | та же схема как параметры инструмента |
| `free_text` | ничего из этого нет | схема в тексте запроса, JSON вынимаем сами |

Режим определяется один раз пробным запросом и дальше не меняется.

**3. Что принимается назад.** Ответ проверяется **одинаково во всех трёх
режимах**. Даже когда API обещал соблюсти схему, проверяются и структура, и
смысл: существует ли такой паттерн, есть ли такие слоты, соответствует ли тип
заполнения типу слота, влезает ли текст, закрыты ли обязательные слоты.

Ремонт чинит механически чинимое — выбрасывает несуществующий слот, подрезает
длинный текст по границе слова, оборачивает текст в список из одного пункта — и
перечисляет, что именно поправил. Что не чинится, вызывает переспрос **с
указанием конкретной претензии**, а не «попробуй ещё раз». Если и это не
помогло, откат на детерминированный планировщик (`ADR-0009`).

## Почему проверяем даже в режиме со схемой

Схема гарантирует форму, а не смысл. Модель может вернуть безупречный по форме
JSON, где `pattern_id` — выдуманный, `slot_id` — из другого паттерна, а текст
вдвое длиннее ёмкости. Ни одно из этих нарушений схема не ловит, а каждое ломает
сборку.

Отдельно: режим `free_text` требует терпимого разбора. Модели регулярно
оборачивают ответ в тройные кавычки или добавляют «Конечно! Вот результат:».
Терять из-за этого ответ незачем — вырезаем внешний объект и продолжаем.

## Следствия

**Хорошо.** 15 сентября адаптация сводится к тонкому клиенту: взять `Request`,
отправить выбранным способом, вернуть строку. Всё остальное написано и покрыто
тестами.

**Хорошо.** Валидатор проверяем без сети: подсовываем ему ответы разной степени
испорченности и смотрим, что он ловит и что чинит.

**Плохо.** Три режима — это три пути, которые надо поддерживать. Цена принята
осознанно: единственная альтернатива — угадать режим и переписывать всё, если не
угадали.

**Плохо.** Ремонт подрезкой портит формулировку. Это последнее средство перед
откатом, и каждая подрезка попадает в список правок, а не происходит молча.

## Что изменилось с тех пор · 17 сентября

**Решение в силе, посылка устарела.** Этот ADR писался в ожидании выданного
организаторами API, характеристик которого мы не знали. Выяснилось (`CTX-TZ`):
**до топ-10 никакого API нам не дают** — инференс свой. Значит модель выбираем
мы, и `OQ-02`, `OQ-03` закрыты для отборочного этапа.

Что это меняет на практике:

- **первый режим, `json_schema`, доступен сразу** и проверен: выбранная модель
  принимает `response_format` со схемой и отвечает строгим JSON. Запасные пути
  пишутся не вслепую, а как страховка на топ-10, где API будет чужой;
- **добавилось четвёртое требование к транспорту, которого в контракте не было:**
  «думающим» моделям надо **отключать размышление**, иначе они тратят тысячи
  токенов и до ответа не доходят. У чемпиона это 23 751 знак рассуждения при
  пустом ответе. Отключается параметром шаблона `enable_thinking: false`;
  приём `/no_think` в тексте **не действует** —
  `WORKLOG/2026-09-17-model-championship.md`;
- **фраза «формулировки поменяются под конкретную модель за полчаса» оказалась
  опасно лёгкой.** Замер: два убранных из промпта слова стоили 11 процентных
  пунктов точности — больше, чем разница между квантованиями модели. Промпт не
  мелочь рядом с контрактом, а величина того же порядка, что выбор модели.

## Что изменилось с тех пор · 24 сентября

**Заменён `ADR-0023`.** Каталог раскладок модели больше не уходит: она строит
колоду из текста до вёрстки и шаблона не видит, а `pattern_id` выбирает код.
Ремонта формулировок и переспроса нет — ответ принимается колодой целиком, иначе
колода собирается путём без модели. Из этого ADR в силе три режима транспорта,
проверка ответа и в режиме со схемой и отключение «думания»; они перечислены в
`ADR-0023`, раздел «Что остаётся от прежних решений».
