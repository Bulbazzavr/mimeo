# ADR-0001. Стадия ANALYZE читает OOXML стандартной библиотекой

## Контекст

Разбор `.pptx` — это ZIP плюс XML. Очевидные кандидаты: `lxml`, `python-pptx`,
стандартные `zipfile` + `xml.etree.ElementTree`.

`python-pptx` удобен, но моделирует не всё, что нам нужно. Он не даёт объектной
модели для `a:themeElements` (`clrScheme`, `fontScheme`, `fmtScheme`), не
разрешает косвенность `p:clrMap`, не считает трансформации цвета `lumMod`/
`lumOff`. Всё это пришлось бы всё равно доставать из сырого XML через
`part.element`, то есть библиотека дала бы удобство ровно там, где оно нам не
нужно, и ничего там, где нужно.

`lxml` даёт полный XPath и быстрее, но это внешняя бинарная зависимость. На
машине разработки её сейчас нет, и в окружении заказчика тоже может не быть.

## Решение

Стадия ANALYZE читает пакет **только стандартной библиотекой**: `zipfile` для
пакета, `xml.etree.ElementTree` для XML.

`ElementTree` поддерживает поиск с картой пространств имён
(`el.findall("a:clrScheme", NS)`) и нотацию Кларка `{uri}tag` — этого достаточно
для нашего обхода, который почти везде идёт по известным путям, а не по сложным
выражениям XPath.

Область действия решения — только ANALYZE. Для стадии COMPOSE вопрос открыт и
решается отдельным ADR: там задача обратная, писать валидный пакет, и там
`python-pptx` вероятно окупится.

> **Предсказание не сбылось, и это записано 19 сентября при вычитке.**
> `ADR-0011` решил обратное: **пакет пишем сами, стандартной библиотекой**.
> Причина оказалась не в удобстве, а в устройстве задачи — сборка идёт
> клонированием готовых частей ZIP, а не построением объектной модели, и
> `python-pptx` здесь не помогает, зато добавляет зависимость. Обязательных
> зависимостей у продукта по-прежнему ноль. `python-pptx` остался, но в другой
> роли: **независимый читатель** собранных файлов в тестах.

## Следствия

**Хорошо.** Ноль внешних зависимостей у ядра анализа. Оно ставится и
запускается везде, где есть Python 3.11. Для open-source сдачи это плюс:
меньше зависимостей — меньше вопросов по лицензиям (`CTX-RULES`).

**Плохо.** Нет полного XPath: выражения вида `//a:srgbClr[@val]` пишутся обходом
вручную. Медленнее lxml, но на файлах в единицы мегабайт это не имеет значения.

**Плохо.** `ElementTree` не сохраняет комментарии и порядок атрибутов. Для
чтения не важно, но означает, что этот же модуль нельзя использовать для
редактирования пакета «на месте» — ещё одна причина, по которой COMPOSE будет
устроена иначе.

## Проверка

Если время разбора шаблона на реальных файлах превысит десяток секунд, решение
пересматривается: скорость разбора неизвестного шаблона — часть сценария питча
(`CTX-SCORE`, критерий 5).

> **Проверено, порог не близко.** Разбор шаблона из нашего корпуса — **0.05 с**
> при пороге в 10 с; самый тяжёлый из выданных, VK Tech с 49 раскладками, —
> 0.2 с. Пересматривать нечего, пункт закрыт 19 сентября.
