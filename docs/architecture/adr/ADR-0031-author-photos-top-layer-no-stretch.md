# ADR-0031. Фото автора — в верхний слой места, без растяжения; раскладку с пустой рамкой ранг не берёт, если есть другая

## Контекст

29 сентября пользователь проверил основной режим: модель, генератор выключен,
фото автора из пакета (VK Tech, текст о магазинах, пять фото с подписями,
`STATE`, очередь, п. 12). Все пять фото встали, но на листе было видно четыре
беды, и пользователь сказал «почини для основного варианта»:

1. **Пустая белая рамка под фото** (раздел из двух тезисов). Штраф
   `_PENALTY_EMPTY_FRAME` из `ADR-0030` мал: раскладка с рамкой набрала 0.79
   против 0.70 у соседней.
2. **Картинка донора поверх фото.** На `p20` карточка — два слоя: непрозрачная
   подложка и над ней объёмная фигура с прозрачностью. Фото легло в нижний
   слой — он ближе по пропорции, — и фигура осталась поверх него. На `p38`
   фото легло в подложку, заходящую на заголовок, хотя верхний слой лежит ниже
   заголовка.
3. **Фото растянуто на 93 %** — 4:3 в месте 2.6:1 (`ADR-0030`, «Следствия»:
   тогда не сделано, запрет растяжения выкинул бы схему-баннер VK Education).
   Кроме того, в `p:pic` сборка меняла только ссылку на файл, и донорская
   `a:srcRect` обрезала уже нашу картинку.
4. **Заголовок наезжает на текст** — переполнение, которое чинит проверка
   вёрстки (`--verify`, `ADR-0005`); в прогоне её не было.

## Решение

1. **Раскладку с пустой рамкой, которую некому залить, `rank` не берёт, если
   разделу годится другая** (`Match.dead_frames`); не годится никакая — берёт,
   раздел не пропадает. Запрет, а не новый штраф: решение пользователя
   28 сентября «пустые рамки обходить». Заменяет п. 3 `ADR-0030` (штраф 0.5
   остаётся для ранга внутри запаса).
2. **Из мест, накрывающих друг друга, картинка идёт в верхнее по слоям донора**
   (`matching._topmost`; порядок слоёв — `Slot.z` из ANALYZE, в JSON раскладки
   не пишется, контракт прежний). Мера перекрытия та же, что у
   `_clear_of_taken`: `backdrop_overlap`, в обе стороны.
3. **Картинка автора в `p:pic` не растягивается** (`compose/substitute.py`,
   `_fit_picture`): своя `a:srcRect` вместо донорской; срезать нужно не больше
   `frame_crop_max` (40 %, тот же предел, что у рамки) — края срезаются по
   центру, больше — картинка вписывается целиком с полями (отрицательная
   `a:srcRect`, ECMA-376 `CT_RelativeRect`; так PowerPoint делает «вписать»,
   свой экспорт `.html` это уже понимает). Схема-баннер VK Education при этом
   не выпадает из колоды — она вписывается, а не выкидывается. Сводка вместо
   «Картинок растянуто» говорит «Картинок не в пропорции места».
4. **Наезд заголовка на текст — дело проверки вёрстки**, нового правила нет:
   прогон с `--verify` ужал переполнения 5 → 0, 5 → 1 и 8 → 4.

## Следствия

- Проверка одной сборкой (VK Tech, пакет с подписями, три варианта,
  `--images off --verify`, промпт колоды 1.7): фото 5 из 5 во всех трёх
  вариантах, белой рамки нет, фото команды вписано без фигуры поверх, схема —
  под заголовком; 164 с на три колоды с живым ответом модели
  (`out/z57/tools-2909/main2-variant-*.png`).
- **Не решено — подпись к фото на слайде.** Строка промпта 1.7 («подпись —
  для выбора слайда, не текст слайда») модель не остановила. Уборка кодом —
  снять тезис, повторяющий подпись фразой, — сделана и откачена той же
  проверкой: раздел «заголовок + фото» ранг отдаёт раскладке-галерее `p49`
  VK Tech (снимки экрана донора, которые зрение потом убирает), и на слайде
  остаются пустые карточки с маленьким фото. Строка в `STATE`, «Разберём потом».
- Планы колод меняются там, где есть рамки под фото и вложенные места под
  картинку, — и у пути без модели: ранг и сборка у путей общие. Сдаточная
  девятка пересобирается в конце (`STATE`, очередь, п. 9).
